# 全产品功能验收与交互修复设计

## 1. 目标

以生产环境真实任务流为标准，完整验证公开功能和登录功能；修复可复现的功能缺陷，并对阻碍任务完成、反馈不明确、移动端不可用或无障碍不合格的交互进行局部重设计。

## 2. 范围

- 公开功能：首页、板块、搜索、股票行情、K 线、财务、AI 分析。
- 账号功能：注册、登录、退出、鉴权过期与登录后返回目标页面。
- 自选功能：分组、新增、编辑成本与备注、移动、删除、云端同步。
- 报告功能：生成、轮询、列表、详情、失败恢复。
- 通知功能：列表、未读数、单条已读、全部已读。
- 体验范围：桌面、平板、手机、键盘操作、缩放、三套主题、加载/空/错误状态。

## 3. 验收策略

按“注册 -> 登录 -> 搜索股票 -> 查看详情 -> 加入自选 -> 编辑持仓信息 -> 生成/查看复盘 -> 处理通知 -> 退出”的主任务链验收。接口测试负责数据与权限契约，Chromium 测试负责用户可见行为，两者都通过才视为功能可用。

## 4. 修复原则

- 功能缺陷先建立失败用例，再做最小修复。
- 交互重设计沿用现有工作台组件、主题 Token 和 Element Plus，不引入依赖。
- 优先修复任务阻断、错误反馈、焦点管理、触控尺寸、横向溢出和状态歧义。
- 不因审查顺手重构无关模块，不修改 schema、共享 API contract 或基础设施。

## 5. 测试数据

使用唯一前缀的临时账号及业务数据。优先通过公开应用接口创建和清理；项目没有删除账号接口时，测试结束后仅保留明确可识别的临时账号，并删除其自选业务数据。不得输出密码、Token 或生产密钥。

## 6. 视觉与交互标准

- 每页只有一个主要操作，次级操作降级展示。
- 异步操作提供 loading、成功和可恢复错误反馈，提交期间禁止重复操作。
- 表单使用可见标签，错误靠近字段并聚焦首个无效输入。
- 键盘可完成导航、弹窗、Tab 与主要表单任务；焦点轮廓可见。
- 手机触控目标不小于 44px，页面无非预期横向滚动或底部导航遮挡。
- 数值、涨跌与图表不能仅依赖颜色传意；三套主题均保持可读。

## 7. 完成标准

- 自动化测试和生产构建通过。
- 全部公开接口、鉴权接口及错误路径符合契约。
- 主任务链在桌面和移动端完成，无 console error 或失败请求。
- 发现的问题均有复现证据、修复验证或明确的外部依赖说明。
- 生产服务、静态缓存和日志状态正常，测试业务数据完成清理。
