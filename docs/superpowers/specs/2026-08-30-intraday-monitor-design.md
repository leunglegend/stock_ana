# 盘中监控工作台设计

日期：2026-08-30  
状态：已确认并实现

## 1. 背景

当前项目已经具备市场概览、板块排行、个股行情/K 线/财务、AI 分析、自选股分组、信号中心和盘后复盘能力，但这些能力分散在多个页面。用户盘中进入系统后，仍需要逐页查看，难以快速判断“哪些自选股值得优先处理”。

本功能新增一个独立的“盘中监控”菜单和页面，将现有接口数据聚合为面向决策的监控视图。它是定时刷新型监控，不承诺逐笔或 tick 级实时行情。

## 2. 目标与非目标

### 目标

- 一次加载市场环境、自选股行情、技术指标和规则信号。
- 按状态和信号生成可解释的“行动队列”。
- 展示个股相对大盘的强弱，帮助用户优先查看跑赢或跑输市场的标的。
- 支持按分组筛选、刷新、排序、跳转个股详情。
- 在数据降级、部分失败和缓存过期时保持页面可用，并明确提示数据状态。
- 为后续服务端预警复用统一的信号结构。

### 非目标

- 不接入逐笔成交、分时行情或交易下单。
- 不新增持仓数量、仓位和总资产模型；第一期只计算记录成本收益率。
- 不在首屏批量请求财务数据；财务和 AI 分析继续按选中股票按需加载。
- 不自动调用 AI 作为排序或风险判断依据；排序以确定性规则信号为准。
- 不在第一期实现自定义预警、邮件/Webhook 推送和回测。

## 3. 用户入口与页面结构

### 路由与菜单

- 路由：`/monitor`
- 菜单标题：桌面端“盘中监控”，移动端“监控”
- 图标：`Monitor`；若项目图标集无该图标，使用 `DataLine`
- 权限：需要登录，沿用现有路由守卫、登录弹窗和登录后回跳
- 菜单顺序：市场、盘中监控、板块、雷达、自选、搜索、报告
- 个股详情仍是隐藏路由，不作为主菜单项

### 页面组件

```text
Monitor.vue
├── MonitorHeader
├── MonitorMarketPulse
├── MonitorActionQueue
├── MonitorTable
├── MonitorInspector
└── StatusState
```

页面行为：

1. 首次进入立即加载一次监控数据。
2. 交易时段默认每 60 秒刷新；非交易时段停止自动轮询，但保留手动刷新。
3. 切换分组时请求新的聚合结果，并取消或忽略旧请求。
4. 刷新期间保留旧数据，避免整页闪烁。
5. 点击行动队列或表格行跳转 `/stock/:code`；返回监控页时保留 URL 查询参数和当前筛选状态。
6. 支持 `?code=600519` 自动选中指定股票，便于从雷达或板块页面联动进入。
7. 选中股票检查器按需调用现有财务和 AI 接口，不阻塞监控矩阵首屏渲染。

## 4. API 契约

### 请求

```http
GET /api/monitor/overview?group_id=all&days=90
Authorization: Bearer <token>
```

参数：

- `group_id`：可选，`all` 表示用户全部分组；传整数表示指定分组。分组必须属于当前用户。
- `days`：可选，支持 `30`、`60`、`90`，默认 `90`。用于计算技术指标和迷你走势。
- `code`：可选，传入自选股代码时仅刷新该股票，供行级重试使用。

### 字段约定

- `as_of` 使用带时区的 ISO 8601 时间；个股 `quote.as_of` 可以是数据源提供的交易日期。
- 所有字段名以 `_pct` 结尾的收益/强弱/距离数值使用百分点：`2.5` 表示 `+2.5%`，`-12.0` 表示 `-12.0%`；不要返回 `0.025` 形式的小数比例。
- `source` 标识数据来源，例如 `kline`、`spot`、`cache`。
- `stale=true` 表示使用缓存或降级数据，不得在界面上标记为实时。
- `errors` 只描述该股票或该聚合阶段的失败，不因单只股票失败而返回 HTTP 500。
- 整体无自选股时返回 200，`items=[]`、`action_queue=[]`，由前端显示空状态。
- 未登录返回 401；非法 `group_id` 返回 404；非法 `days` 返回 422。

## 5. 后端架构与数据流

建议新增：

- `backend/app/routes/monitor.py`：路由和参数校验。
- `backend/app/schemas/monitor.py`：响应模型，包括市场、摘要、监控项、信号和错误模型。
- `backend/app/services/monitor_service.py`：聚合、去重、并发、缓存和排序。
- `backend/app/services/signal_rules.py`：统一的后端技术信号规则。

处理流程：

1. 从数据库读取当前用户分组和自选股。
2. 根据 `group_id` 过滤，并按股票代码去重；同一只股票属于多个分组时只请求一次行情/K 线。
3. 以受控并发拉取每只股票的一份日 K 数据。建议通过 `stock_data` 增加“单次拉取并构造监控快照”的内部能力，同时得到最新行情、指标、收益和 sparkline，避免分别调用行情和 K 线接口造成重复请求。
4. 统一执行信号规则：
   - `trend-above-ma20` / `trend-below-ma20`
   - `macd-golden-cross` / `macd-death-cross`
   - `rsi-overheated` / `rsi-oversold`
   - `breakout-20d` / `drawdown-20d`
   - `cost-gain` / `cost-loss`
5. 使用市场概览缓存计算市场环境和相对上证强弱：`个股涨跌幅 - 上证涨跌幅`。
6. 生成摘要和行动队列，返回成功项、部分失败项和数据状态。

### 市场环境规则

- 若涨跌统计缺失，环境为“未知”。
- 上涨家数占有效总家数 `>= 60%` 且涨停数 `>=` 跌停数：`偏强`。
- 下跌家数占有效总家数 `>= 60%` 且跌停数 `>` 涨停数：`偏弱`。
- 其他有效情况：`分化`。

### 监控状态规则

- `attention`：存在任一风险类信号（跌破 MA20、MACD 死叉、较大回撤、低于成本阈值，或数据错误）。
- `strong`：不存在风险类信号，且至少存在两个正向信号。
- `neutral`：其余有效数据。
- `error`：该股票无法得到足够的有效 K 线或行情数据。

### 缓存与并发

- 市场概览沿用现有缓存。
- 监控快照按股票代码缓存 60 秒，缓存键包含代码和 `days`。
- 单次请求的股票并发数限制为 4～6，具体值通过常量配置。
- 单只请求超时或失败时优先返回该股票最近缓存，并设置 `stale=true`；没有缓存则返回该项错误。
- 不在监控接口中批量加载财务和 AI 内容。

## 6. 前端实现边界

`Monitor.vue` 只消费聚合接口；建议将现有 `stockSignals.js` 的阈值和展示类型迁移为共享常量或后端契约，避免前后端长期出现不同结论。迁移期间前端可以保留本地信号计算作为接口失败时的展示兜底，但不能覆盖后端已返回的信号。

检查器选中股票后调用：

- `GET /api/stock/{code}/financial`
- `GET /api/stock/{code}/analyze`（用户主动点击）

监控矩阵至少支持：

- 分组、状态、涨跌幅、相对强弱、信号严重度排序。
- 只看行动队列、只看上涨、只看有成本记录等筛选。
- 桌面端表格 + 右侧检查器；移动端列表化展示，检查器改为抽屉或底部面板。

## 7. 错误处理与可访问性

- 首次整体失败：显示错误状态和重试按钮。
- 部分失败：保留成功股票，失败股票显示错误原因和单只重试入口。
- 数据过期：在页面头部和对应行显示“数据已延迟”，同时保留原始更新时间。
- 空分组：显示空状态和跳转“自选”管理页的入口。
- 所有刷新、错误和选中状态提供 `aria-live` 或明确的键盘焦点反馈，沿用项目现有 `StatusState` 和路由切换焦点行为。
- 不将颜色作为唯一信号表达方式，同时显示文字标签和数值原因。

## 8. 测试与验收

### 后端

- 路由鉴权、参数校验和用户分组隔离。
- 同一股票跨分组只发生一次数据拉取。
- 并发请求上限生效，单只失败不影响整体响应。
- 缓存命中、过期、降级和 `stale` 标识正确。
- 市场环境、相对强弱、状态和行动队列排序规则正确。
- 无自选股、无市场数据、K 线不足时响应结构稳定。

### 前端

- `/monitor` 路由、桌面侧边栏、移动端导航和活动态正确。
- 未登录访问能弹出登录框，登录后回跳 `/monitor`。
- 加载、空数据、整体错误、部分错误和过期数据状态正确。
- 分组切换、手动刷新、自动轮询、筛选、排序和单只重试正确。
- 点击行动队列进入个股详情，返回后监控页状态可恢复。
- 桌面端检查器和移动端抽屉布局可用。

### 验收标准

1. 进入 `/monitor` 后一次接口请求即可得到市场摘要、自选股矩阵和行动队列。
2. 20 只以内自选股不会因重复请求导致明显的请求风暴。
3. 每个信号都能显示触发原因和关键数值。
4. 页面明确区分正常、缓存、降级和失败数据。
5. 单只股票失败时，其余股票和市场摘要仍可正常使用。
6. 现有 `/watchlist` 的分组和自选管理能力不受影响。

## 9. 后续扩展

在本设计稳定后，可以复用 `signals` 和 `action_queue` 增加：

- 用户自定义预警和消息中心通知。
- 信号历史快照及 1/5/20 个交易日效果回看。
- 股票到板块的反向映射和板块联动。
- 持仓数量、交易记录和组合收益分析。
