# 股票分析前端工作台完全重构设计

## 1. 目标

将现有 Vue 3 前端重构为面向桌面研究场景的专业 A 股工作台，同时保证移动端功能完整、关键流程连续、数据来源可信。

本轮只修改前端，保持现有后端 API 和响应契约不变。任何业务字段必须直接来自现有接口，或由接口字段通过本文明确的公式派生。接口不支持的数据不进入页面。

## 2. 设计决策

- 产品方向：专业研究工作台，高密度、强扫描、低装饰。
- 使用场景：桌面研究优先，移动端完整可用。
- 数据优先：红色表示上涨，绿色表示下跌；操作色不与行情色混用。
- AI 定位：摘要和解释层，不替代行情、K 线和财务数据。
- 范围边界：不新增后端接口，不使用模拟业务数据。
- 导航主线：发现市场 -> 研究个股 -> 加入跟踪 -> 盘后复盘。

## 3. 信息架构

### 3.1 一级导航

桌面固定侧栏与移动端底部导航统一为四项：

1. 市场概览
2. 板块发现
3. 我的自选
4. 复盘报告

股票搜索上移为全局命令，不再占用一级导航。完整搜索结果仍由 `/search` 承载。个股详情与报告详情是上下文页面，不出现在一级导航中。

### 3.2 全局外壳

- 桌面：固定侧栏、顶部命令栏、主内容区。
- 顶部命令栏：数据获取状态、全局搜索、通知、用户入口。
- 全局搜索：任何路由均可通过按钮、`Ctrl/Cmd + K` 或 `/` 打开。
- 路由上下文：市场进入板块、板块进入个股时保留查询参数和返回位置。
- 鉴权续航：访问受保护页面时保存目标路由，登录成功后返回原目标。

## 4. 设计系统

### 4.1 视觉原则

- 使用中性表面色构建层级，避免大面积紫色、渐变和营销式 Hero。
- 红绿只表达涨跌，并同时提供正负号和数值。
- 页面区块使用紧凑面板、数据表格、指标条和分段 Tab。
- 不使用卡片嵌套卡片，不为普通面板增加悬浮位移动画。
- 数字使用 `tabular-nums`，保证列对齐和刷新稳定。

### 4.2 Token 范围

统一定义并接入以下语义 Token：

- `surface / surface-muted / border`
- `text / text-muted / link / focus`
- `positive / negative / warning / error / ai`
- spacing、type scale、radius、shadow、z-index、motion duration
- 图表网格、坐标轴、MA5/10/20、MACD/KDJ/RSI 色板

现有 `tokens.css` 需要真正由全局样式引入。组件内不直接散落 raw hex；ECharts 配置也消费统一图表 Token。

## 5. 页面设计与接口映射

### 5.1 市场概览

首屏内容：

- 三大指数与涨跌幅、两市成交额。
- 上涨、下跌、平盘、涨停、跌停家数及上涨占比。
- 热门行业板块及领涨股。
- 登录后的自选行情，最多展示 5 只并逐项加载。
- AI 市场点评，按需重新生成。

数据契约：

| UI 模块 | 接口 | 字段或规则 |
| --- | --- | --- |
| 指数与市场宽度 | `GET /api/board/market/summary` | `sh_* / sz_* / cyb_* / rise_count / fall_count / flat_count / limit_* / total_amount` |
| 上涨占比 | 同上 | `rise_count / (rise_count + fall_count + flat_count)`；分母为 0 时不展示 |
| 热门行业 | `GET /api/board/industry` | `name / change_pct / leading_stock / leading_change / stock_count` |
| 自选行情 | 自选列表 + `GET /api/stock/{code}` | 最多 5 只，并发上限 4，逐行状态 |
| AI 点评 | `GET /api/board/market/ai-summary` | SSE 正文；失败不影响其他市场数据 |

不展示指数分时曲线、放量/新高标签或未经交易日历验证的“交易中”状态。更新时间是客户端记录的成功响应时刻。

### 5.2 我的自选

- 分组使用可横向滚动的 Tab，高频切换一步完成。
- 支持新建、重命名、删除分组。
- 表格支持名称/代码筛选、涨跌幅排序、仅看已设成本。
- 行情按单股接口受控并发加载；单行失败可单独重试。
- 支持编辑成本和备注、进入详情、移除股票。
- 加自选时选择目标分组，成功反馈明确显示分组名称。

真实字段来自自选分组与条目接口，以及 `GET /api/stock/{code}`。

只允许以下派生：

- 每股盈亏 = 最新价 - 成本价
- 成本收益率 = 每股盈亏 / 成本价

成本为 0 或缺失时不计算。由于接口没有持仓股数，不展示组合总市值、组合总成本、组合总盈亏或仓位。

### 5.3 个股详情

固定股票头部显示名称、代码、加自选操作、最新价、涨跌额和涨跌幅。下方展示今开、昨收、最高、最低、成交量和成交额。

主体使用四个独立 Tab：

| Tab | 接口 | 内容 |
| --- | --- | --- |
| 行情 | `GET /api/stock/{code}` | `StockInfo` 全部可用字段 |
| K 线 | `GET /api/stock/{code}/kline` | 日/周/月 K、OHLCV、MA5/10/20、MACD、KDJ、RSI |
| 财务 | `GET /api/stock/{code}/financial` | PE、PB、总市值、ROE、净利润、营收、毛利率、净利率、报告期 |
| AI 分析 | `GET /api/stock/{code}/analyze` | 用户主动触发的 SSE 分析 |

各 Tab 独立加载和失败。财务 `null` 字段显示 `--`，不推算。AI 评分 JSON 解析成功时显示评分；解析失败时只展示 Markdown 正文。AI 未配置或连接失败不影响其他 Tab。

### 5.4 搜索

- `GET /api/stock/search?q=` 返回 `code/name` 后立即渲染。
- 对前 20 个真实命中调用 `GET /api/stock/{code}`，并发上限为 4。
- 每行独立显示行情加载、成功或失败状态。
- 最近搜索仅保存在本机，可清除；不提供硬编码热门推荐。
- 加自选时选择分组，不静默加入未知分组。
- 不提供接口不支持的全市场排行榜或 AI 评分列。

### 5.5 板块发现

- 行业与概念使用 Tab 切换。
- 列表基于响应字段支持筛选与排序：涨跌幅、成交额、换手率、上涨/下跌家数、股票数。
- 点击板块加载 `GET /api/board/{type}/{name}/stocks`。
- 成分股展示代码、名称、价格、涨跌幅、换手率、PE 和总市值。
- 桌面使用详情侧栏，移动端使用全屏面板。
- 读取首页传入的 `name/type`，自动打开目标板块；关闭和返回时保留上下文。

### 5.6 复盘、通知与鉴权

- 报告列表使用分页数据，展示日期、真实状态、覆盖股票数、市场摘要、创建/完成时间。
- `POST /api/reports/generate` 只消费 `report_id/message`。
- 生成后每 5 秒使用现有列表或详情接口查询 `pending/generating/completed/failed`；完成、离开页面或持续 2 分钟后停止，超时后保留手动刷新。
- 不展示接口没有提供的百分比进度。
- 生成接口只支持今日报告；历史失败报告不显示“重新生成”。
- 报告详情展示 `market_summary / highlights / stock_reports / risk_notes`。
- 个股评分只在 `analysis_text` 中评分 JSON 成功解析时显示。
- 通知使用现有列表、未读数、单条已读和全部已读接口。
- `type=report` 且存在 `ref_id` 时跳转报告详情。
- 401 时保存当前目标、登出并弹出登录；登录成功后恢复目标路由。

## 6. 数据流与状态

每个页面遵循统一状态模型：`idle -> loading -> success | partial | empty | error`。

- `loading`：使用尺寸稳定的骨架，不改变布局。
- `partial`：已成功模块正常显示，失败模块就地重试。
- `empty`：说明缺少什么，并提供真实可执行动作。
- `error`：显示原因类别和恢复操作，不用只有顶部 toast 的方式隐藏错误。
- SSE：展示连接中、生成中、完成和中断；离开页面或重新请求时关闭旧连接。
- `null` 与数值 `0` 分开处理，不能用真假判断把合法的 0 当成缺失。
- AI 与报告 Markdown 必须先经过 HTML 清理再交给 `v-html`，不直接渲染未经处理的模型输出。

### 6.1 用户数据持久化边界

- SQLite 是登录用户资料、自选分组、自选条目、复盘报告和通知的唯一事实来源。
- 继续使用现有 `users / watchlist_groups / watchlist_items / daily_reports / stock_reports / notifications` 表和 `user_id` 关联，不新增表或迁移。
- 密码只保存现有 `password_hash`，前端和数据库均不保存明文密码。
- 前端不再将 `userInfo` 长期写入 `localStorage`；应用启动后通过 `GET /api/auth/me` 获取用户资料并只保存在 Pinia 内存。
- 浏览器可保留现有 JWT 以维持登录状态；退出或 401 时立即清理。未登录自选数据仍可按现有行为保存在本地，登录同步后以 SQLite 数据为准。
- 页面刷新时先恢复令牌，再验证 `/api/auth/me`；验证完成前使用明确的鉴权初始化状态，避免误判为已登录或未登录。

## 7. 响应式规则

- `>= 1024px`：固定侧栏和顶部命令栏，表格与多栏工作台优先。
- `768-1023px`：侧栏改为抽屉，多栏内容降为单栏。
- `< 768px`：底部四项导航，顶部全局搜索；页面不保留桌面侧栏占位。
- 移动端宽表转换为摘要行，点击进入全屏详情或底部面板。
- 板块详情、添加自选和复杂表单在移动端使用全屏或底部面板。
- 验证视口：`360x800`、`390x844`、`768x1024`、`1440x900`。

## 8. 无障碍与交互

- 所有关键路径可使用键盘完成。
- 可点击行使用链接或按钮语义，不用只绑定点击事件的 `div`。
- 图标按钮提供 `aria-label` 和 tooltip。
- 全局搜索使用 `role="dialog"`、焦点陷阱、方向键选择、Escape 关闭和焦点归还。
- 路由切换后焦点移动到主标题。
- 使用 `:focus-visible` 提供统一 2px 焦点环，不移除 outline。
- 触控目标至少 `44x44px`，移动端正文至少 `16px`，不禁用页面缩放。
- 动态错误与完成反馈使用 `aria-live`，颜色不是唯一状态提示。
- 尊重 `prefers-reduced-motion`。

## 9. 组件边界

建议组件层次：

- 外壳：`AppShell`、`DesktopSidebar`、`MobileNav`、`CommandBar`、`GlobalSearchDialog`
- 通用：`PageHeader`、`SectionPanel`、`StatusState`、`EmptyState`、`Skeleton`
- 数据：`StockIdentity`、`PriceDisplay`、`MetricCell`、`DataTable`、`FilterBar`
- 业务：市场指标、板块列表、自选表格、股票详情 Tabs、报告列表与阅读器

基础组件只在消除真实重复或统一交互契约时创建。`AppCard` 改为无默认 hover 位移的面板壳，禁止卡片嵌套。

## 10. 验证与验收

### 10.1 接口一致性

- 为每个页面建立 UI 字段到响应字段的映射测试或 fixture 测试。
- 确认所有展示字段来自当前 schema 或本文公式。
- 验证 `null`、0、空数组、部分请求失败、401 和 SSE 中断。

### 10.2 功能路径

- 搜索 -> 个股详情 -> 选择分组加入自选。
- 市场首页 -> 指定板块 -> 成分股 -> 个股详情，并保留返回上下文。
- 未登录访问自选或复盘 -> 登录 -> 自动回到目标页。
- 通知 -> 标记已读 -> 报告详情，未读数同步减少。
- 今日报告生成 -> 真实状态刷新 -> 完成后可打开详情。

### 10.3 视觉与可用性

- 四个目标视口无非预期横向滚动、遮挡或文本溢出。
- 关键路径可纯键盘完成并具有可见焦点。
- 图表非空、尺寸稳定、切换周期和指标正常。
- 红涨绿跌一致，数字对齐，加载过程无明显布局跳动。

### 10.4 工程验证

- `npm run build`
- 项目现有测试；若无前端测试框架，本轮新增最小必要测试基础前需单独确认依赖变更。
- 使用 Playwright 对桌面和移动端进行主要页面截图、交互与控制台错误检查。

## 11. 非目标

本轮不实现以下能力：

- 批量行情后端接口
- 全市场排行榜
- 稳定的结构化 AI 评分 API
- AI 今日选股或推荐池
- 持仓股数、仓位和组合级盈亏
- 任意历史日期报告重新生成
- 后端 schema、数据库、依赖或环境模板变更

这些能力必须在后续独立需求中先定义后端契约，再进入页面设计。
