# 方向一 · 页脚静默增资(全站常驻「股东随手增资」入口)

> 设计决策轮 · 2026-09-04 · 打赏入口设计线一
> 方向人设锁定:**股东情怀版(适度)** · 入口位置:**页脚** · 支付:**微信/支付宝个人收款码(无后端资金流)**
> 只出方案,不写业务代码;本文件不涉及后端。

---

## 1. 一句话定位

> **在最不显眼的地方给一句最像「注脚」的话,点开才知道这是一次不上市的「A 轮融资」。**

全站页脚放一行与免责声明同级的股东梗小字(常驻、不闪、不红点、不自动弹),点击才弹出「增资」面板,面板内微信/支付宝双码随缘金额、一句致谢即止。没有积分、没有档位、没有排行榜、没有「已支持 N 人」——把「要钱」这件事藏进一个本来就该存在的页脚里。

设计张力一句话:**「可被发现,但绝不主动打扰」**——入口的价值不是点击率,而是让想支持的人 30 秒内找到一条体面的路。

## 2. 入口落点:页脚里放什么

### 2.1 先纠正一个前提:全站目前**没有页脚**

只读调研结论(钉在真实代码上):

- `frontend/src/components/Layout.vue` 的骨架是:`DesktopSidebar / el-drawer(移动抽屉) / .app-shell__main(内:CommandBar + MobileNav + `<main>` RouterView) / GlobalSearch`。**没有 `<footer>`**。
- `frontend/src/components/app/MobileNav.vue` 是**顶部横向滚动导航**(CommandBar 之下),不是底部 tab 栏,也没有任何 fixed/absolute 元素压住页面底部——即移动端内容底部是「空的、可到达的」。
- 全站 grep `copyright/©/ICP/备案/footer`:**没有任何版权行、备案行、站脚声明**。`数据仅供研究参考,不构成任何投资建议` 这类合规句目前只藏在 `LoginModal.vue` 登录面板里,普通用户不进登录框就永远看不到。
- 页面级「footer」只存在于组件内部(`SectionPanel/AppCard` 的 `#footer` 插槽、表格分页条),都不是站级。

**推论:这不是「在已有页脚里塞一行」,而是「顺手补一个真正的站级页脚,再在页脚里放一个安静的词」。** 页脚因「合规声明 + 产品署名」而存在,增资入口只是这条注脚里可点的最后一个词——这天然解释了它为什么低调。

### 2.2 桌面端落点

在 `Layout.vue` 的 `</main>` 之后、`.app-shell__main` 内追加一个站级 `<SiteFooter />`,一条通栏细条(建议 CSS:高约 36px、`border-top: 1px solid var(--border-subtle)`、字号 `var(--font-size-xs)`、文字色 `var(--text-tertiary)`、背景跟随内容区 `var(--surface-canvas)` 或透明)。

栏内分左右两组:

- **左(不可点,纯声明):** `析股研究台 · 数据仅供研究参考,不构成任何投资建议`
- **右(可点,唯一的入口):** `股东可顺手增资 ↗`(普通文字链接样式,非按钮)

视觉强度严格压到「注脚级」:默认 `text-tertiary`,与左侧声明同色同字号;hover 才变 `text-link` 并加下划线;focus-visible 走全局 `--focus-ring`。不发光、不跳动、不加徽标、不加 emoji 图标。

为了让短页面下页脚也「贴底」而不悬在页面半空,建议给 `.app-shell__main` 加 `display:flex; flex-direction:column`,让 `.app-shell__content` 承担 `flex:1`(内容区现有 `min-height` 可保留)。这是经典的 sticky-footer 布局,是本次唯一的结构性 CSS 改动,风险低、可回退。

### 2.3 移动端落点与兜底判断

**结论:移动端不新增第二个入口,用同一个页脚即可——页脚在移动端不会被吃。**

理由:

- 移动端没有任何固定底栏覆盖(见 2.1),内容自然滚动,页脚就是每个页面滚到底的最后一行;
- 采用上面的 sticky-footer 布局后,内容不足一屏的短页面,页脚会贴在一屏底部(不用滚动也能瞄到);内容长则跟在最后一个卡片之后,属正常站脚;
- 移动端页脚文案自动缩短为单行:`析股研究台 · 股东可顺手增资 ↗`(免责声明在窄屏隐藏或换行置后,由 `@media (max-width: 767px)` 决定)。股东梗入口保留,合规声明仍留在桌面与宽屏,避免窄屏被两行注脚干扰。

**「替代兜底」选项(本期倾向不做,列给评审权衡):** 若评审认为移动端「滚到底才发现」过于隐蔽,最低成本的兜底是在 `CommandBarUtilities.vue` 现有的「更多(`MoreFilled`)」下拉里追加一个纯文本项 `股东增资`——完全复用现成下拉,不新增任何常驻布局。**默认建议不加**,原因见 §6 与 §9 顾虑 1:方向一的灵魂就是「单入口、低打扰」,第二入口会稀释克制感,也会与方向三(先点赞层)的入口分工打架。

## 3. 交互流程(0 → 点击 → 弹出 → 扫码 → 关闭)

每一步用户看到什么、系统做什么:

| 步骤 | 用户看到 / 做的 | 系统行为 | 打扰等级 |
|---|---|---|---|
| **0 · 常驻态** | 每个页面底部注脚行,右侧一行 `股东可顺手增资 ↗`,与免责声明同色同字号,毫不起眼 | 无任何动作;不弹窗、不红点、不计数、不进场动画 | 0(纯静态) |
| **1 · 悬停** | 文字从灰变主题蓝并出现下划线;`title` 提示「析股研究台靠爱发电,欢迎股东顺手增资」 | 仅 CSS 变色;无其他特效 | 0 |
| **2 · 点击** | 中央弹出紧凑 Dialog(约 460px),遮罩压暗背景 | `el-dialog` 打开;焦点移入面板;页面不跳转、无路由变化 | 用户主动触发 |
| **3 · 阅读面板** | 股东梗主句 → 一句说明 → 微信/支付宝双码并排,各配一句「金额随缘」 | 纯静态展示两张收款码图;无表单、无金额输入、无接口 | 用户主动停留 |
| **4 · 扫码支付** | 用另一台手机(或长按/存图后到对应 App 扫相册)完成转账 | **无任何检测、无回调、无「到账」判断**(约束:不伪造支付成功) | 无 |
| **5 · 关闭** | 点「继续看盘」按钮,或点遮罩 / × | 关闭面板,焦点归还触发元素;**不弹任何 toast、不发「打赏成功」** | 0 |

关键约束落地:

- **没有「我已支付」按钮。** 面板内固定一行小字说明「转账成功后无需任何操作,也不用回传截图」,把「没有反馈」预先讲成「不需要反馈」,避免用户找不存在的确认键。
- **关闭即结束。** 关闭后 24 小时内不会以任何形式再次出现或提醒——因为它从不主动出现(见 §6)。

## 4. 打赏面板结构

### 4.1 布局(建议,遵循现有 Dialog 语言)

复用 **`el-dialog`**(项目已有注册;参照 `WatchlistAddDialog.vue` 用 `@update:model-value`、`LoginModal.vue` 隐藏标题栏做自定义头部的写法),宽度 `min(460px, calc(100vw - 24px))`,允许 `close-on-click-modal`(无表单、无提交中态,安全)。

自上而下:

1. **头部(自定义,不用标准 title)**:左侧一个小徽标——本地引入 `@element-plus/icons-vue` 的 `CoffeeCup` 图标放进带边框的小方框(复用 `LoginModal` 里 `auth-brand__mark` 的做法),右侧一个 eyebrow 小字如 `VOLUNTARY · 非公开募股`;右上角 ×(element 自带)。
2. **主句**(§5 文案,≤30 字):黑体大字,如「本台 A 轮融资开放——本轮唯一股东:你。」
3. **副句说明**(2~3 行,§5):讲清「个人维护、自费、钱去哪、纯自愿」。
4. **双码并排区**:一个两列 grid(`grid-template-columns: 1fr 1fr`,gap `--spacing-3`),每列一张「收款卡」:
   - 卡 A 顶部:`微信支付`(可用微信绿但建议用中性色,避免与涨跌色混淆)→ 卡身白色底收款码图(`<img>` 静态资源,方形,宽 `min(100%, 168px)`)→ 卡脚:`微信扫一扫 · 金额随缘`;
   - 卡 B 同构,标题 `支付宝`,卡脚 `支付宝扫一扫 · 金额随缘`;
   - 卡与卡之间给足呼吸,选中/悬停有 `--surface-panel-muted` 浅底与 `--border-subtle` 描边(不必做成大按钮)。
5. **信任小字**:收款卡下方一行掩码收款方,如 `收款方:析股台 · *哥(支付前请核对)`——**只放作者设定的掩码昵称,绝不放全名/账号**,降低「扫码被钓鱼/扫错人」的疑虑。
6. **关闭行(footer)**:右侧一个主按钮 `继续看盘`(el-button primary);左侧放致谢小字(§5)。

### 4.2 金额怎么处理(建议)

个人收款码在「不预设金额」时,由付款方在 App 里自行输入金额与备注。**建议全部不设固定金额、不写金额档**:

- 不渲染任何「加仓 / 战略投资 / 6.6 / 8.8 / 66 / 88」档位按钮——金额档位被产品前提明确禁止,也会让「股东梗」变味成「卖课档位」;
- 双码卡脚统一写 `金额随缘`,配合主句/副句把「随缘」讲成股东人设而不是将就;
- **作者落地建议**:生成个人收款码时保持「金额不固定」;(若所用 App 支持)预填默认备注为 `析股台增资`,方便作者对账;把两张码图存成 png 放入 `frontend/src/assets/tip/`(见 §7),由静态资源引用,不经任何接口。

### 4.3 致谢 / 按钮文案

- 关闭按钮主文案:**`继续看盘`**(不写「残忍离开」「下次一定」这类反向催促);
- 面板底部致谢小字:**「不打赏也欢迎白嫖——你来了,就是支持。」**;
- 转账指引小字:**「转账成功后无需任何操作,心意已收到,也不用回传截图。」**(诚实替代伪造回调)。

### 4.4 给作者的收款码落地清单(方便评审对「作者稍后自贴码」有感)

1. 用微信「收付款→二维码收款」、支付宝「收钱」各生成个人收款码;
2. 金额保持**不固定**;若能设默认备注则填 `析股台增资`;
3. 两张码图导出为方形 png,命名 `wechat.png` / `alipay.png`,放 `frontend/src/assets/tip/`;
4. 在面板里配置一个**掩码收款方昵称**(如 `*哥`),与码图同时展示;
5. 建议作者定期核对账单——页面不会替你做任何到账检测。

## 5. 股东情怀文案集(逐场景)

> 人设校准:**把打赏包装成「给平台 / 给 AI 打工仔增资、信仰充值」;可自嘲行情(绿 / 跌 / 打工),可玩「不上市 A 轮」「唯一股东是你」;绝不承诺收益、绝不诱导未成年人。**
> 颜色提醒:本产品遵循 A 股习惯 **红涨绿跌**(`--color-up-500` 红 / `--color-down-500` 绿),「绿/跌/打工」是安全的自嘲对象。

### 5.1 入口小字(≤12 字)

| 方案 | 文案 | 字数 | 语气 | 备注 |
|---|---|---|---|---|
| **R1(推荐)** | **股东可顺手增资** | 7 | 克制、股东味足 | 与右侧免责声明同色,低调 |
| R2 | 给 AI 打工仔添电费 | 10 | 自嘲、人味 | 「打工仔」接住人设但略长 |
| R3 | 顺手请研究员喝咖啡 | 11 | 客气 | 股东梗弱,偏「请客」 |
| R4 | 这里也可以增资 | 8 | 最淡 | 过于含糊,不推荐单独用 |

悬停 `title`(不占版面):`析股研究台靠爱发电,欢迎股东顺手增资。`

### 5.2 面板主句(≤30 字)

| 方案 | 文案 | 字数 | 备注 |
|---|---|---|---|
| **R1(推荐)** | **本台 A 轮融资开放——本轮唯一股东:你。** | 约 18 | 把「打赏」升维成「A 轮融资」,股东梗一击即中 |
| R2 | 恭喜你当选股东:不用出很多,一点点就好。 | 约 21 | 温和,降低心理压力 |
| R3 | 这是本台唯一一次不上市的融资,对象只有股东。 | 约 22 | 梗更展开,适合想多解释一层的场景 |

### 5.3 副句解释(2~3 行,说明「为什么 + 钱去哪 + 纯自愿」)

> **R1(推荐):**
> 析股研究台由一个人维护,行情、服务器、AI 的电费都是自费。
> 如果它帮你少踩过几个坑,欢迎小额增资——这笔钱不拿去扩产,
> 只够请这个 AI 打工仔喝几杯咖啡。
>
> **R2(自嘲行情款,可作点缀小字,不替代 R1):**
> 最近大盘一片绿,但这里绝不绿你的钱包。

### 5.4 关闭 / 致谢语

| 场景 | 文案 |
|---|---|
| 关闭按钮 | **继续看盘** |
| 面板底部致谢(常驻小字) | 不打赏也欢迎白嫖——你来了,就是支持。 |
| 转账后说明(替代伪造回调) | 转账成功后无需任何操作,心意已收到,也不用回传截图。 |
| 可选:关闭瞬间 | 不发 toast、不追踪,保持静默(默认不做任何弹出反馈) |

### 5.5 合规小字(面板内,必放)

> **本页为自愿赠与,非购买、非投资,不构成任何收益承诺。**
> **未成年人请先取得监护人同意——或者直接白嫖,我们一样欢迎。**

合规句用 `--font-size-xs` + `--text-tertiary`,放在二维码区与 footer 之间,不喧宾夺主但必须可读。

## 6. 防打扰与克制策略

1. **入口零主动:** 页脚行是纯静态文本,不弹窗、不红点、不角标、不进场动画、不首访引导;任何一次出现都必须是用户主动滚到底 + 主动点击的结果。
2. **一个入口即可,不加第二入口:** 桌/移共用同一页脚(§2.3)。「更多」下拉兜底列为可选项但默认不做,避免与方向三的「先点赞后打赏」层在入口上打架。
3. **不消费社交压力:** 不展示「已支持人数 / 股东数 / 最近谁打赏」,不做排行榜,不因打赏改变任何可见状态(无会员、无改名、无头衔)。
4. **无 dismiss 状态需求:** 因为它从不主动打扰,「关闭后长期不再出现」的诉求天然不成立;不需要为此引入 localStorage 状态。若未来想加「第二次打开面板换一句问候」的变体,届时再加一个 `已读支持页` 布尔即可,**本期明确不做**。
5. **退出成本为零:** 面板无表单、无倒计时、无「再想想」弹层;点遮罩 / × / 继续看盘任意方式离开都干净利落,离开后无任何挽留手段。
6. **动效克制与无障碍:** 不加弹跳/抖动动画;尊重 `prefers-reduced-motion`(可复用 `LoginModal.vue` 里已写的 reduce 覆盖);入口是真正的 `<button>`,带 `aria-label`,焦点态可见。

复用现状:**`el-dialog` 已全局注册**;图标本地从 `@element-plus/icons-vue` 引入(`CoffeeCup`/`Coin` 均在本地依赖中,已确认存在);颜色/间距/圆角全部走 `styles/tokens.css` 的 CSS 变量;项目惯例是组件在 `<script setup>` 内**局部 import**(见 `WatchlistAddDialog`、`CommandBarUtilities`),无需在 `elementPlus.js` 注册新东西。

| 文件 | 动作 | 内容 |

| `frontend/src/components/TipDialog.vue` | **新增** | 基于 `el-dialog` 的增资面板:头部徽标 + 主句/副句 + 双码并排 + 信任小字 + 合规小字 + footer(`继续看盘`) |
| `frontend/src/components/Layout.vue` | **编辑(小)** | 引入并渲染 `<SiteFooter />`;`.app-shell__main` 改 `flex-direction: column` + `.app-shell__content { flex:1 }` 以实现 sticky-footer(§2.2) |
| `frontend/src/components/app/CommandBarUtilities.vue` | **不编辑(可选兜底)** | 仅当评审采纳「更多下拉加一项」时再改 |
| `frontend/src/assets/tip/wechat.png`、`alipay.png` | **新增(作者提供)** | 个人收款码静态图,`<img>` 直接引用 |
| 后端 / 路由 / store | **无改动** | — |

**是否需要前端状态?** 不需要。经 `store/index.js`、`store/user.js` 与视图结构核对:面板完全静态,无「支持过/股东数/云端记录」需求;金额不落库、不发送,本地也不存支付痕迹(隐私干净)。唯一可选的 localStorage 布尔仅服务未来文案变体,本期不做。

改动面合计:**2 个新组件 + 1 处 Layout 小改 + 2 张作者提供的静态图**,半天以内的工作量,零后端、零路由、零 store。

## 8. 边界 / 合规 / 成本 / 风险

**边界与合规**

- **无资金流:** 不接任何商户 API、不做支付回调、不伪造「到账成功」;页面只展示静态收款码,「转账成功无需操作」的文案把期望讲清楚,是合规且诚实的做法。
- **定性为「自愿赠与」:** 面板内明确写「非购买、非投资、无收益承诺」,避免被解读成购买服务或理财产品;不提供任何「打赏后解锁/加群/荐股」的交换承诺(付费换荐股是红线)。
- **不承诺收益:** 全文案只谈「喝咖啡/电费/增资」,不出现「让预测更准/收益更高/进 VIP」等字眼;自嘲只指向行情(绿/跌)与打工,不指向用户收益。
- **未成年人保护:** 合规小字显式提示需监护人同意,并用「白嫖也一样欢迎」降低诱导。
- **不诱导、不比较:** 无金额档位、无排行榜、无社交证明,天然规避「攀比式打赏」。
- **与既有合规行的关系:** 借新增页脚把「数据仅供研究参考,不构成投资建议」落到全站每个页面底部(此前只在登录框内),反而是合规加分项。

**风险与对策**

| 风险 | 对策 |
|---|---|
| **信任风险:** 公网页面上展示个人收款码,可能被截图冒用 / 用户担心是钓鱼 | 页面只放掩码收款方(如 `*哥`)+ 明确「支付前请核对」;码图仅本地静态资源、不走任何外链;入口只在站内页脚,不与任何弹窗广告同框 |
| **无到账检测:** 作者收不到「谁付了」的即时反馈 | 页面不承诺到账检测;建议作者开收款 App 的消息提醒 + 定期核对账单;文案统一为「心意已收到」 |
| **二维码被替换 / 篡改(供应链):** 若有人改掉 assets 里的码图 | 码图随前端代码一并入库、走版本管理;评审与作者发布前核对一次 |
| **「页脚入口近乎零转化」:** 过于克制可能导致几乎没人点 | 这是方向一的**主动取舍**;若上线后确实需要免费表达层兜底,应交给「方向三(先点赞后打赏)」接住,而不是在本方向内加料 |
| **Layout 结构改动回退风险:** `.app-shell__main` 改 flex 列 | 影响面小且可回退;内容区现有 `min-height` 保留,可先做桌面截图回归(首页/监控/个股)再合入 |

**成本**:约 0.5 人日(2 组件 + 1 布局小改 + 2 张作者码图);无服务器、无第三方支付接入、无持续费用;二维码本身零成本。最大成本其实是作者后续**人工对账**的隐性时间——方案里已用「默认备注 `析股台增资`」尽量降低。

## 9. 给评审的「3 个亮点 + 2 个顾虑」

### 亮点

1. **一行注脚就是全部入口。** 不做图标、不做红点、不做自动弹窗,入口与免责声明同级同色;全站不需要任何「支持过/股东数」类状态,面板纯静态,克制成本极低。
2. **先补了一个本就该有的站级页脚,再谈打赏。** 现状全站没有任何页脚/版权/合规行(只有登录框里有一句免责声明);本方向顺手让「数据仅供参考、不构成投资建议」落到每个页面底部——增资入口只是这条真实注脚末尾可点的词,「顺带感」让它不像在要钱。
3. **金额与「反馈」都被诚实处理。** 不设金额档、不渲染「我已支付」、不伪造到账——用「转账后无需任何操作,心意已收到」把「无反馈」讲成「不需要反馈」,既守住合规底线,也保住了股东梗的体面。

### 顾虑

1. **「克制」与「可发现」的矛盾:** 入口在页脚、移动端要滚到底,注定点击率会很低;若团队真正想要一个「能运转起来」的打赏闭环,可能还得靠方向三的免费表达层兜底——本方向需要评审确认:低转化是否可接受(这正是它「不像要钱」的代价)。
2. **个人收款码的公网信任与人工对账:** 展示个人码有被冒用/被疑钓鱼的信任成本,且作者无法从系统侧感知「谁付了、付了多少」,只能靠账单人工核对;若作者很在意到账可见性,可能需要后续在码上叠加额外标识,或考虑方向二/方向四的载体。

## 10. 落地自查(交卷前)

- **是否真的只需要页脚一个入口?** 是。桌面与移动共用同一页脚;移动端无固定底栏遮挡、滚动可达,不需要第二个入口;「更多下拉加一项」仅作为评审可选杠杆,默认不加。
- **是否克制到不像在要钱?** 是。入口是一条 `text-tertiary` 小字、hover 才显色;无自动弹窗、无徽标、无社交证明、无金额档、无挽留弹层、关闭即静默;唯一的「张扬」是打开面板后那句股东主句——而那恰好是点进来的人想看的彩蛋,而不是门外的吆喝。
