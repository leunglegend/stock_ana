# 方向二「顶栏 · 信仰充值」— 点赞/打赏入口设计方案

- 日期：2026-09-04
- 范围：只读调研 + 打赏入口设计（产品决策轮，只出方案不落业务代码）
- 性质：设计候选，评审直接读本文打分
- 方向一句话定位：**在顶栏右侧放一枚"低调但一眼可见"的充值胶囊，点开是一张股东情怀版「增资」打赏卡——全站常驻、无分档、无到账检测、无后端资金流。**

---

## 1. 方向一句话定位

**「信仰充值」**：入口常驻全站顶栏右侧、靠近铃铛/头像，首次以文字胶囊形式呈现（看得见），点开后是一张「给析股研究台增资」的双码打赏卡；一旦点开过一次，自动从文字胶囊降级为纯图标（不打扰）。把"要钱"翻译成股东梗，但所有承诺都收在"自愿支持、无收益、无权益"的合规边界内。

---

## 2. 入口落点：顶栏右侧的具体形态

### 2.1 先钉死"顶栏"到底是哪个元素

经只读调研，本项目**没有传统意义的 App/DesktopSidebar 顶栏**——真正的全站顶栏是 `Layout.vue` 中主内容区上方的 **`CommandBar.vue`**（桌面侧栏 `DesktopSidebar` 只是左侧导航，不是顶栏）。它每一页都渲染，是唯一的全站常驻横条，天然是"全站入口"的落点。

```
┌─────────────────────────────────────────────────────────────┐
│  DesktopSidebar(固定左栏)                                    │
│  ┌──────────┐  ┌──────────────────────────────────────────┐  │
│  │ brand XG │  │ CommandBar: 日期·盘后│ 搜索 / │ 右簇       │  │
│  │ 导航...   │  │                    │       │  [入口][铃铛][工具]│  │
│  │ ...       │  └──────────────────────────────────────────┘  │
│  └──────────┘  MobileNav(仅<768 第二行横向页签)                 │
│               <main> RouterView …                             │
└─────────────────────────────────────────────────────────────┘
```

`CommandBar` 当前是**三列 grid**（`grid-template-columns: minmax(220px,1fr) minmax(240px,320px) minmax(220px,1fr)`，移动端变 `auto 1fr auto`）：
- 左列：汉堡菜单（仅移动）+ 交易日/盘后 + 状态点；
- 中列：`command-bar__search`（点开 GlobalSearch 的"搜索股票、代码或板块"）；
- 右列 `.command-bar__right`：`<NotificationBell />`（登录才显示）+ `<CommandBarUtilities />`（主题切换 / 登录按钮或用户头像chip / 移动端 ⋯ 溢出菜单）。

### 2.2 桌面端（≥1024）：文字胶囊

- **形态**：一枚小胶囊按钮——左侧一枚 `Coin` 图标（金色 `--color-warning-500`）+ 右侧文字「信仰充值」（4 字）。
- **位置**：放进 `.command-bar__right` 的**第一个子元素**（即铃铛的左侧、贴着铃铛/头像簇的内侧）。改动只插一行 `<TipPayEntry />`。
- **样式基调**：不走主色实心按钮（那是"登录"的层级），用 `transparent 底 + 1px var(--border-subtle) 描边 + var(--text-secondary)`，hover 时描边转 `--color-warning-500`、文字转 `--text-primary`，只比普通工具图标"重"半档。高约 32px、与搜索框/登录按钮同高，不额外增高顶栏。
- **hover/文案**：`el-tooltip` 提示（见 §5 文案）。hover 不做弹跳/动画，纯色变。

### 2.3 移动端（<768）与平板（768–1023）

| 断点 | 右簇现状 | 入口形态 | 会不会挤占 |
|---|---|---|---|
| ≥1024 | 铃铛(登录) + 主题/登录或头像chip | **文字胶囊**「信仰充值」（约 92px） | 否：右簇空间充裕（1024 视口下右簇可用约 540px，现占用约 240px + 胶囊仍有余量） |
| 768–1023 | 铃铛 + 主题 + 登录/头像chip（date 仍在） | **纯图标胶囊**（隐藏文字，仅 `Coin` 图标 32px） | 基本否：把文字收掉只占 ~36px；避免 768px 边界与日期/搜索抢宽度 |
| <768 | 汉堡 + 搜索 +（铃铛）+ ⋯溢出按钮 | **纯图标按钮**（44px 触控区、28px 图标），置于铃铛左侧 | 登录态会变"汉堡+搜索+图标+铃铛+⋯"，44+44+44 固定位；375px 下搜索框仍约 150px。**Plan B（见下）**兜底超窄屏 |

- **为什么移动端不放文字**：顶栏移动端只有 48px 高、搜索框是主轴，任何文字胶囊都会显著压缩搜索框。用纯图标满足"一眼能看见"，把梗交给弹层。
- **Plan B（超窄 / 仍嫌挤）**：把入口收进 `CommandBarUtilities` 的 ⋯ `MoreFilled` 菜单，加一行「信仰充值」。仅当实现后真机评测右簇拥挤时启用，避免过度设计。
- 不放进 `MobileNav` 页签行（那是页面级导航，打赏不属于页面）。

### 2.4 无障碍与热区

- 图标/胶囊都必须是原生 `<button>`，带 `aria-label="支持打赏作者"`（图标态）或文字本身可读（胶囊态）。
- 胶囊点击不改变 URL、不跳路由，纯弹层动作，因此**不侵犯**主导航任何页签的激活态。

## 3. 交互流程

```
[顶栏胶囊/图标] --点击--> [打赏卡 el-dialog 弹出] --用户操作-->
    ├─ 扫码（个人收款码，金额自输） ── 不检测、不回调，作者后台自行看到
    ├─ 关闭按钮 X / 点遮罩 / ESC ── 关闭，并将状态机升为"已点开"（降级图标）
    └─ 「下次一定」/「暂时收起」 ── 轻关闭 / 30 天隐身
```

- **默认不自动弹出**：不搞"首次访问延迟 3 秒弹卡"这类强打扰；入口永远是被动触发。
- **防手滑误点**：
  - 它与铃铛共用右簇但视觉差异大（胶囊带文字/金色 Coin vs 铃铛图标），不存在同形误触；
  - 打开的成本极低（关掉即可），**不做二次确认**，避免把打赏门槛做高；
  - 弹层用 `el-dialog` + `close-on-click-modal=true`，ESC 可关——点了发现不是想要的动作，一键回到原状态；
  - `@click.stop` 防止与顶栏其它事件串扰。
- **"点开过"即降级**：首次呈现文字胶囊（引导认知），用户点开过一次后，`localStorage` 记录 `openedCount`，此后同一浏览器只显示纯图标。**不彻底隐藏**（常驻是前提），只是降低声量。

## 4. 打赏卡结构

- **容器**：复用项目已有弹窗语言 `el-dialog`（对齐 `WatchlistAddDialog` 的 `width: min(720px, calc(100vw - 24px))` 写法；打赏卡更小，取 `min(560px, calc(100vw - 24px))`），`.el-dialog` 圆角 14px、标题隐藏或极短，右上 X 关闭。卡片整体用 `--surface-panel`，内部分区用 `--border-subtle` 分隔。
- **整体布局**（文字 + 双码并排）：

```
┌───────────────────────────────────────────────┐
│  eyebrow：给析股研究台的一笔增资                  │ ✕
│  主句：给『析股研究台』充点信仰，行情绿了我们也不慌。 │
│  副句：你的每一笔增资，都会变成更稳的行情源、        │
│        更勤快的 AI 助理，和作者的一杯续命咖啡。     │
│  ┌──────────┐   ┌──────────┐                   │
│  │ 微 信     │   │ 支付宝    │                   │
│  │ 收款码图   │   │ 收款码图   │                   │
│  │(作者自贴)  │   │(作者自贴)  │                   │
│  └──────────┘   └──────────┘                   │
│  提示：长按识别/用对应 App 扫码，金额随缘、自行输入。  │
│  金额无档位、无套路；打赏≠购买任何服务或权益。       │
│  ───────────────────────────────────────────    │
│  脚注：不承诺收益/不构成投资建议/未成年人勿打赏       │
│  [ 下次一定 ]   [ 暂时收起这个入口 ]                │
└───────────────────────────────────────────────┘
```

- **金额处理（个人收款码限制）**：
  - 微信/支付宝**个人收款码**无法在页面预置金额，只能"用户扫码后自行输入"。因此**不做金额分档按钮**（也符合产品前提"不做加仓档位"）。
  - 用文案把限制转成优点："没有档位、没有套路、金额随缘"。
  - 两张二维码在移动端允许换行堆叠（`flex-wrap: wrap`），每张图约 200–220px。
- **二维码区**：作者稍后自贴码图 → 放 `src/assets/tip/wechat.png`、`alipay.png`。开发期用带品牌名描边的占位块。图片下标注「长按识别二维码」，并写死兜底说明"若无法识别，可在对应 App 搜索作者留下的收款备注"（作者自填）。
- **是否需要"下次再说"式轻关闭**：**需要**。右下放两枚轻按钮——
  - 「下次一定」：普通关闭，仅升级状态机；
  - 「暂时收起这个入口」：`el-button link` 细字，写入 30 天隐身时间戳（真正的防打扰出口）。
  - 不设"彻底删除入口"（作者需要长期入口，且会被其它入口顶替，30 天足够克制）。

## 5. 股东情怀文案集（逐场景）

> 语气基准：与 `LoginModal`「把每一次登录，变成研究开始」同源的机构研究台口吻，掺一点行情自嘲；**绝不承诺收益、不出现"返利/解锁/铁粉等级"，不诱导未成年人**。全站文案出现"增资/入股"均为玩梗，配一行小字澄清。

| 场景 | 建议文案 | 说明 |
|---|---|---|
| 入口文字（≤10 字） | **「信仰充值」** | 主推。4 字、有自嘲的游戏充值梗转译。备选 A「为爱增资」更温柔；备选 B「请 AI 恰饭」更年轻但离股东梗远。 |
| 悬浮 tip（桌面） | 「为这台研究台增资——作者和打工的 AI 都靠它续命」 | 首次 hover；点开过一次后改为「来都来了，需要时再投喂」。 |
| 弹卡 eyebrow | 「股东专线 · 增资入口」 | 开场即立住"股东"人设。 |
| 面板主句（≤30 字） | **「给『析股研究台』充点信仰，行情绿了我们也不慌。」**（23 字含标点） | 自嘲行情绿、兜住"信仰"。 |
| 副句 | 「你的每一笔增资，都会变成更稳的行情源、更勤快的 AI 助理，和作者手里的一杯续命咖啡。」 | 把打赏落成用户可感知的"平台变好"，而非权益。 |
| 金额提示 | 「没有档位、没有套路：扫码后金额随缘，由你亲手输入。」 | 把个人码不能预设金额的限制转为"轻松无压力"。 |
| 扫码引导 | 「长按识别，或用对应 App 扫一扫」 | 双码并排，各自标注「微信 / 支付宝」。 |
| 致谢 | 「作者在后台会看到每一笔增资——先替这座研究台说声：多谢股东。」 | 无到账检测下，用"作者会看到"替代虚假的成功回调。 |
| 关闭语 | 「下次一定」 | 梗式轻关闭，礼貌拒绝 + 不尴尬。 |
| 收起入口 | 「暂时收起这个入口」 | 细字 link，30 天。 |
| 合规脚注（两行小字） | ①「打赏是自愿支持，不是投资行为；不承诺收益、不构成任何投资建议、不解锁任何功能。『增资/入股』只是玩梗。」②「未成年人请勿打赏——把零花钱先投资给自己，就是最好的复利。」 | 一句话讲清边界，另一句把"不诱导未成年"用股东梗温柔说出。 |

> 备选主句（更皮，可选轮换）：「行情绿了没关系，信仰永远满仓。」——注意避免"满仓"暗示收益，仅作氛围句；若评审觉得过度，用主句即可。

## 6. 防打扰策略

- **不自动弹**：只在被点击时出现；无动画诱导、无脉冲、无红点（红点语义是"有新东西"，打赏没有，不做假红点）。
- **三级声量状态机**（同一浏览器，`localStorage` 键 `tip_pay_meta`）：

| 状态 | 判定 | 入口形态 |
|---|---|---|
| 未点开（新访客） | `openedCount === 0` 且未 snooze | 文字胶囊「信仰充值」——把"这里有打赏"讲清楚 |
| 已点开 ≥1 次 | `openedCount ≥ 1` | 降级纯图标（Coin）——不隐藏，只降噪 |
| 主动收起 | `snoozedUntil > now` | 完全隐藏 30 天（期满回到未点开态或图标态） |

- **视觉克制**：胶囊默认不是主色，是描边次级色；唯一"情感色"是那枚金色 Coin 图标，暗合"打赏/金币"但不喧宾夺主。
- 实现上全部是纯前端 `localStorage` 读写（仿 `watchlistPersistence.js` 的 try/catch 模式），**无账号绑定、无后端**，因此换设备/清缓存即回到默认，可接受（个人站场景）。

### 7.2 复用与不新建的设计资产

- 弹层：`el-dialog`（对齐 `WatchlistAddDialog.vue` 的宽度写法与 `LoginModal.vue` 的圆角/隐藏标题手法）。
- 视觉：只用现有 design tokens（`--surface-panel/--border-subtle/--text-secondary/--color-warning-500/--spacing-*`），不引新色板、不引图片图标库；入口图标用 Element Plus 自带的 `Coin`（已确认 `@element-plus/icons-vue` 含 `coin`）。
- 响应式：`useResponsive()` 已有 `isDesktop/isMobile`；入口内部按需用 CSS 媒体查询（≤767 / ≤1023）切胶囊↔图标即可，尽量少引 JS。
- 状态：无需新增 Pinia store（全局唯一、非共享），用 `tipPayState.js` 的模块级 localStorage 帮助函数即可。

### 7.3 数据流

```
TipPayEntry(读取 tip_pay_meta → 决定 pill/icon/隐藏)
  └─ click → TipPayDialog(visible=true)
        ├─ 关闭/下次一定 → openedCount+1 并落库 → 入口自动降级为 icon
        └─ 暂时收起 → snoozedUntil=now+30d → 入口隐藏
```

零网络请求、零后端路由、零埋点（如需统计点击次数可后续再议，v1 不引入）。

## 8. 边界 / 合规 / 成本 / 风险

- **边界**：入口与登录态解耦（未登录可打赏）；不做"打赏解锁报告/去广告"等权益绑定——因为**没有到账检测，无法核验**，任何权益绑定都会变成骗局或失信。
- **合规**：
  - 用个人收款码做"赞赏"，无商户 API、无资金流，符合个人小站惯例；页面文案明确「打赏≠投资、≠购买服务、不构成投资建议」；
  - "增资/入股/满仓"等词一律在卡内澄清为玩梗，避免任何"股权/返利/收益承诺"的误读；
  - 显式写「未成年人请勿打赏」，不诱导未成年付费；
  - 与全站既有免责口径一致（`LoginModal`：数据仅供研究参考，不构成任何投资建议）。
- **成本**：作者时间成本 = 自贴两张码图 + 前端一个下午；运行成本 ≈ 0（无后端、无第三方支付手续费描述——个人收款码的费率/提现规则由平台决定，本方案不介入）。
- **风险**：
  - 二维码图片被人替换/盗链 → 只读本仓库静态资源，风险低；但仍建议码图直接进 `assets` 而非外链。
  - "打赏入口"在金融机构合规语境可能敏感，但本项目定位是个人研究工具站，已用免责兜底。
  - 个人收款码若被滥用（如刷单/未成年人）平台可能风控 → 文案 + 脚注已做软性对冲，且无真实到账检测，作者需自行留意账单。

## 9. 给评审的 3 个亮点 + 2 个顾虑

**亮点**
1. **"点开即降级"的自克制状态机**：把"常驻但不骚扰"落成可执行的三级形态（文字胶囊 → 纯图标 → 30 天隐身），成本只有一个 `localStorage` 键，不需要任何复杂体系。
2. **文案与产品语言同源**：把"要钱"翻译成股东梗（增资/信仰充值），并把最难写的合规话术（不承诺收益、未成年人、不构成投资建议）直接织进打赏卡的可见文案里，而不是塞进角落小字。
3. **改动面收敛且全复用**：挂点只动 `CommandBar` 一行 + 2 个新组件 + 2 张码图；弹窗/按钮/色彩全部复用现有 `el-dialog` 与 design tokens，零新依赖、零后端。

**顾虑**
1. **顶栏右簇是高频区**（搜索/通知/账户），任何常驻按钮都在稀释其密度；登录态 + 768–1024 窄屏下文字胶囊可能偏挤，需靠"降级为图标 + 媒体查询"控制——若评审仍觉得打扰，应整体退到 Plan B（⋯ 更多菜单）。
2. **双码静态 + 无到账检测 = 没有反馈闭环**：可能出现"用户投了、页面没谢"的错位；且"增资/入股"梗有被个别用户读成"真有回报"的歧义——需要卡内那行「打赏≠投资、无任何回报」的显性兜底来压住。

## 落地自检：它有没有侵犯顶部导航的主任务？

- 顶部主任务是**搜股票 / 看行情 / 切页面**，三者都发生在顶栏的搜索框、中央内容区与左侧/页签导航，打赏入口**不拦截、不置顶、不弹窗抢占**其中任何一步。
- 入口是**二级被动动作**（点了才展开卡），不改变 CommandBar 任何既有控件的尺寸与可用性；胶囊宽约 92px、图标态仅约 32px，在右簇以"最轻的一档强调"存在。
- 状态机保证：**看过一次的人**之后只见到一枚安静的小图标——"看得见，但不上赶着"。
- 结论：**克制达标**。真正需要警惕的不是功能本身，而是右簇总宽度（已在 §2.3 用媒体查询 + Plan B 双保险兜住）。
