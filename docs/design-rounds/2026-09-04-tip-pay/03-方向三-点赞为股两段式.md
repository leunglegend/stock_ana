# 方向三「点赞为股 · 两段式」设计方案

> 设计决策轮 · 2026-09-04 · 打赏入口设计线三
> 范围:前端 Vue3 + Element Plus,无后端、无资金流、不接支付回调。
> 阅读对象:3 名评审。本文件只做方案,不落地业务代码。

---

## 0. 一句话定位

> **先给一个零成本、能点亮、有仪式感的「股东表达」出口(点赞=投一票),再把打赏重新包装成「顺带增资」——不逼捐,把要钱的尴尬变成股东梗的会心一笑。**

为什么「先点赞再打赏」比直接要钱更让人舒服:

1. **门槛心理学(foot-in-the-door)**:直接弹「打赏」是在用户还没建立任何关系时就要钱,防御最高;先让用户花 0 元做一个有成就感的动作(点亮、持股 1 股),再谈「顺带」,心理阻力小一个量级。
2. **给「不掏钱」留了体面出口**:用户已经用「点赞」完成了表达,拒绝「增资」时不是拒绝你这个人/平台,只是「不加注」——白嫖体验完整,不产生亏欠感。这对一个以研究工具立身的产品尤其重要:**永远不能让免费用户觉得自己是二等股东。**
3. **把打赏从「交易」变成「梗」**:本产品受众是股民,「股东情怀」是他们最熟的母语。打赏被说成「增资/信仰充值」,配合自嘲行情绿,是幽默而非索取;幽默是唯一能反复出现的要钱姿势而不招烦的包装。
4. **产品上反而更克制**:入口常驻但只点亮一次;「顺带增资」只在点赞这个自然动作之后才出现,频率天然被用户的主动行为锁死(详见 §6),比定时弹窗骚扰小得多。

## 2. 常驻位选择:顶栏右侧(主选)vs 页脚(备选)

### 2.1 现状盘点(读代码结论)

- 全局壳在 `Layout.vue`:桌面为左侧 `DesktopSidebar`(168px / 平板收成 64px 图标栏),主区顶部是 `CommandBar`(通栏,桌面 3 栏 grid),内容区是各页。**不存在任何全局页脚**,`DesktopSidebar` 底部只有一行「交易日·盘后/时钟/行情状态」的小字状态块。
- `CommandBar` 右侧 `.command-bar__right` 当前渲染:`NotificationBell`(仅登录后显示)→ `CommandBarUtilities`(桌面:主题切换 + 登录按钮/用户菜单;≤767px:主题与账号收进「更多」下拉,只留更多图标)。移动端 CommandBar 右侧空间约 = 铃铛 + 更多;下方另有 `MobileNav` 横向滚动导航条。
- 移动端断点由 `useResponsive()` 提供(`isMobile` <768)。顶栏高度:桌面 40px(`--command-bar-height`),移动 48px,触控目标惯例为 44px(`--mobile-control-height`)。

### 2.2 主选:顶栏 CommandBar 右侧,作为常驻图标钮

**位置**:`NotificationBell` 之后、`CommandBarUtilities` 之前,插入独立组件 `<SupportButton />`(登录/未登录都显示)。

**理由**:

1. **点赞本质是个「动作」,不是链接。** 页脚位置的读者心智是「备案/版权/免责」,天然低交互、低发现率;而「投票/支持」需要一个能被随手点亮、且能看到点亮结果的地方——顶栏右侧是唯一跨所有页、跨登录态、桌面移动都常驻的交互热区。
2. **与现有铃铛同构、零新布局成本。** 顶栏右侧已经是一个「图标动作区」,加一个 32px(移动 44px)的图标钮不需要改任何布局或 CSS 变量;页脚则要新建一整条跨页布局,改动面大得多。
3. **同一挂点自动解决响应式。** `CommandBar` 在所有路由、桌面/移动都在;只改一个文件即全站生效(§7)。
4. **「顺带增资」的二次引导天然锚定按钮。** 打赏卡从按钮的 popover 弹出,路径最短(§3)。

**移动端适配**:≤767px 时按钮保持为**纯图标钮(44×44)**,不带文字,与铃铛/更多对齐;点赞文案只在桌面图标旁显示短词(可选),移动靠 aria-label 与点亮动画传达。当前移动右侧 = 铃铛 + 更多,加入后 = 铃铛 + 点赞 + 更多,总宽约 132px,375px 屏下与搜索框共存无压力(实测 `grid-template-columns: auto minmax(0,1fr) auto` 的右列本就自适应)。

### 2.3 备选:页脚 / 侧栏底 —— 为何不选

| 候选 | 现状 | 否决理由 |
|---|---|---|
| 全局页脚 | **不存在**,需新建一条跨页 footer | 改动面大;阅读心智 = 静态信息,不配「投票」动作;移动端还多占一屏高度 |
| `DesktopSidebar` 底部状态块 | 只在桌面全宽侧栏可见 | 平板收成 64px 图标栏、移动端整个侧栏收进抽屉,**不常驻**,违背入口常驻前提 |
| 每页页头 / 个股页 | `StockHeader` 有「加入自选」动作 | 点赞对象是**平台整体**,不是个股;放个股页会被误读成对该股票的背书(见 §8),且无法跨页常驻 |

## 3. 两段式动线(把每步文案写具体)

### 3.0 全局状态约定

「点赞态」只存本机(localStorage),三个可见层:

- **未点亮** = 还没投过票 → 显示「点赞」入口。
- **已点亮(已投票)** = 本机点过赞 → 按钮金色实心。
- **增资与否** = 与点赞态分离,不因点赞自动发生,只在「顺带增资?」被点或点已亮按钮后进入打赏卡。

### 3.1 第①步:点赞(免费,一点即亮)

**触发**:点顶栏「点赞」图标钮。
**行为**:图标由空心瞬间填充为金色实心 + 轻微 scale 弹跳动画(200ms,尊重 `prefers-reduced-motion` 时去掉动画),随即弹出「股东确认卡」popover(见下)。这一下**不弹任何打赏**。
**第①步文案(点亮反馈)**:

| 用途 | 文案(主选) | 长度 |
|---|---|---|
| 点亮 toast 首行(股东确认卡标题) | **「表决成功。本机股东名册 +1。」** | ≤12 字 |
| 副句(解释这份「股」是什么) | 「你持股『鼓励』1 股,行权价 0 元,不盯盘、不套牢。」 | 自嘲式消解「持股」的严肃性 |
| 隐藏小字(诚实声明) | 「此票记在本机浏览器,换设备/清缓存不随行——属彩蛋,不属实缴登记。」 | 见 §8 防误导 |

> 措辞上用「名册 +1」「持股 1 股」这类**只对用户本人说的、单数、虚拟**表述;严禁「已有 N 人点赞」这类**统计性**表述(§8.1)。

### 3.2 第②步:对已点赞者浮现「顺带增资?」

**时机**:**只在用户刚完成点赞的当下**,弹出「股东确认卡」;卡片里第二行动线才是「顺带增资?」。除此之外,**不做任何页面加载即弹、定时弹、路由切换弹**——被动骚扰面为零。

**出现位置**:锚定顶栏按钮、向下展开的轻量 popover(与 `NotificationBell` 的右侧下拉同一视觉语言,宽度约 320px;移动端 `placement=bottom-start`,`width:min(320px, calc(100vw - 24px))`)。

**频率 / 防打扰策略**(详见 §6):自动邀请终身最多 3 次、每天最多 1 次、被选「不再问」后永久闭嘴;被邀请过仍可**手动**点已亮的按钮进打赏卡(用户主动,不视为骚扰)。

**第②步文案(引导语,核心要让「不花钱的人不尴尬、想花钱的人会心一笑」)**:

| 用途 | 文案(主选) |
|---|---|
| 引导主句 | 「这票研究员收下了。若哪天想让它更有分量——入口在下面,金额随意。」 |
| 「顺带增资?」行动钮(固定语) | 「**顺带增资?**」 |
| 拒绝出口(不尴尬) | 幽灵按钮「先不了,白嫖也是股东权益。」 |
| 永久关闭入口 | 更小字链接「以后别再提增资」 |

想花钱的人看到「顺带增资?」会心一笑(把打赏说成股东追加认购);不花钱的人有体面出口,甚至「白嫖也是股东权益」把不花钱本身也包装成一种自嘲权利——**两边都不亏**。

### 3.3 第③步:进入打赏卡(双码 + 致谢)

点「顺带增资?」或再次点已点亮按钮 → 打开 `el-dialog` 打赏卡(结构见 §4)。
打开后本地记 `tipCardOpenedAt`;致谢文案即刻可见,不做任何「支付成功」判定(无回调、不伪造,§8)。

### 3.4 点亮态在现有组件体系里的表达

现有体系里「用户设置的持久点亮态」最自然的表达就是 **Element Plus 的 warning(金)语义 + 实心图标**,与「加入自选→已收藏(warning 高亮)」一致;铃铛未读点用 up 红,那是「提醒」语义,**不借用**。具体:

- 未点亮:`el-button text` + 空心拇指(SVG stroke,`var(--text-secondary)`)+ 可选文字「点赞」。
- 已点亮:同按钮 + 金色实心图标 + 浅金底 `var(--color-warning-50)`(参考 `notification-item.unread` 的 `primary-50` 用法),可选文字「已一票」。点击不再重复点亮,而是打开「股东确认卡/打赏卡」(防止误触反复取消,保护两段式动线)。
- 撤回:不放在主按钮(防误触),放进股东确认卡里的一行小字「收回这一票」(见 §6)。

### 3.5 动线示意(线框文字版)

```
[顶栏右侧]  ◎点赞 →(点击)→ ●点亮(金色)
                                  │
                                  ▼  (仅此刻自动出现一次)
              ┌─────────────────────────────┐
              │ 🗳 表决成功。本机股东名册+1。│   ← ①
              │ 你持股『鼓励』1股,行权价0元  │
              │                             │
              │   [顺带增资?]  (幽灵)先不了   │   ← ② 轻引导

                    │ 点「顺带增资?」 / 日后点已亮按钮
                    ▼
```

## 4. 打赏卡结构

参考 `LoginModal` 的分栏 el-dialog(`width:min(760px, calc(100vw - 32px))`,`@closed` 归还焦点、滚动锁定),桌面左右分栏、移动单列堆叠。

| 区块 | 内容 |
|---|---|
| 左(或上,移动) | **双码并排**:微信收款码 | 支付宝收款码,各配说明「保存二维码 → 打开微信/支付宝 → 扫一扫→相册」;码图放 `frontend/src/assets/support/`,用 `import` 进 Vite 打包,作者日后直接**覆盖同名图片文件**即可换码,不改代码 |
| 右(或下,移动) | 主句(≤30 字)+ 金额建议(文案层)+ 致谢 + 合规小字 |
| 底部 | 免责与边界小字(§8) |

**金额处理建议**:个人静态收款码无固定金额能力,故**不做金额档位按钮**(也符合「无金额分档」锁定前提),只在文案层给「随缘区间」玩梗,并主动压小额(兼顾风控):

> 「金额随缘:一杯奶茶区间(6.66 / 8.88 / 18.88)刚刚好,超过 99 请三思——平台不搞大额集资,研究台吃不了那么多。」

**主句与致谢文案集**(详见 §5,这里给推荐落点):

- 主句(≤30 字):**「研究不收费,服务器要养;各位股东,量力增资。」**
- 扫码后即见致谢:**「扫码即赠,无需截图回传对账;作者看到到账,会挑个交易日默默说谢谢。」**

## 5. 股东情怀文案集(逐场景,可直接抄用)

> 风格基调:幽默、可自嘲行情绿/打工;**绝不承诺收益、不诱导未成年人、不把打赏说成投资回报**。所有文案集中在一个 `supportCopy.js`,方便评审逐条看、作者日后改。

### 5.1 入口按钮(点赞 = 股东?)

| 场景 | 主选 | 长度 | 备选 |
|---|---|---|---|
| 未点亮按钮文字 | 「点赞」(tooltip:点个赞,给研究台投一票,免费,不伤本金) | 2 字 ✅≤10 | 「投一票」「点个赞」 |
| 已点亮按钮文字 | 「已一票」(tooltip:你已是本机股东,感谢投票) | 3 字 ✅≤10 | 「已赞」 |

### 5.2 点亮反馈(股东话术)

- **主选(确认卡标题)**:「表决成功。本机股东名册 +1。」(12 字)
- 副句(消解严肃):「你持股『鼓励』1 股,行权价 0 元,不盯盘、不套牢、随时可撤。」
- 可选行情梗(按当日 A 股涨跌轮换,取一条):
  - 绿盘日:「看了一天绿,这只票至少是红的(指按钮)。」
  - 红盘日:「难得飘红,顺手给研究台也添点喜气。」
  - 平盘日:「大盘平,心意不平——这票研究员收下了。」

### 5.3「顺带增资?」引导语(核心:不花钱不尴尬、花钱的会心一笑)

- 引导主句:「这票研究员收下了。若哪天想让它更有分量——入口在下面,金额随意。」
- 行动钮(固定):「**顺带增资?**」
- 拒绝出口:「先不了,白嫖也是股东权益。」(把不花钱也包成一种自嘲权利)
- 温和提醒:「今天不增也没关系,这票已经记下了,不催。」(一次性致意,非弹窗)
- 永久关闭:「以后别再提增资。」

### 5.4 打赏面板主句与致谢

| 用途 | 文案 | 约束 |
|---|---|---|
| 面板主句 | **「研究不收费,服务器要养;各位股东,量力增资。」** | 计 18 字 ✅≤30 |
| 面板主句备选 | A「打赏不是买收益,是给这台研究台加口粮。」B「一杯咖啡,给 AI 研究台加一箱油。」C「增资全凭自愿,行情全凭运气。」 | — |
| 金额建议 | 「金额随缘:一杯奶茶区间刚刚好;超过 99 请三思,平台不搞大额集资。」 | 压小额、护风控 |
| 扫码即见致谢 | 「扫码即赠,无需截图回传;作者看到到账,会挑个交易日默默说谢谢。」 | 诚实:不伪造成功 |
| 未成年人行(合规) | 「未成年的小股东:这一票心意已收到,增资这步先记在自选里,长大再说。」 | 温和劝阻 |

### 5.5 撤回与告别

- 撤回投票(确认卡内小字):「收回这一票」
- 撤回后 toast:「票已收回,研究台照常营业,欢迎随时再投。」

## 6. 防打扰与克制策略(本地态怎么存、会不会变骚扰)

**核心原则:所有「增资邀请」都挂在用户主动的「点赞」动作之后,绝不主动弹。**

| 策略 | 规则 | 存储字段 |
|---|---|---|
| 不主动弹 | 页面加载 / 路由切换 / 定时,**永不自动弹**任何打赏 | — |
| 自然频率锁 | 自动「顺带增资?」只可能出现在**刚点赞后**;且终身最多 3 次、同一天最多 1 次 | `inviteAutoShown`、`lastInviteAt` |
| 永久关闭 | 用户点「以后别再提增资」→ 之后连刚点赞也不自动带增资引导(只留普通点亮确认) | `suppressInvite: true` |
| 手动可达 | 已点亮按钮**随时可点**进股东卡→打赏卡(用户主动,不算打扰) | — |
| 撤回 | 已点亮用户可在确认卡内「收回这一票」,回到未点亮态;撤回后不再带任何增资引导 | `liked: false` |
| 会话抑制 | 本次会话已打开过打赏卡 → 本次会话不再自动出现增资引导 | session 变量(不进 localStorage) |

**会不会变成骚扰?** 不会的机制性理由:①没有任何「到点提醒/回流提醒」;②入口按钮本身不跳数字、不加红点、不换文案勾引;③唯一自动出现点是「点赞成功」的顺带一提,且被终身 3 次/日 1 次/永久关闭三重闸门;④白嫖用户点掉「先不了」后,按钮依旧金色、功能完整,后续仅靠用户自己点按钮才再见入口。

**本地态怎么存**:参考 `store/user.js`(setup store + localStorage 直接读写)与 `store/watchlistPersistence.js`(`STOCK_KEY` + load/save 纯函数,异常 try/catch 兜底)两种惯用写法。本功能建议**新增独立小 store + 独立持久化**,不混入自选逻辑,key 名见 §7。

## 8. 边界 / 合规 / 成本 / 风险

### 8.1 本地「点赞/股东数」会不会让作者误以为真实统计 —— 会,所以设计上消灭它

- **UI 永不出现统计数字**:不显示「已有 N 人点赞/支持」,因为没有后端,任何计数都只是单浏览器幻觉;显示它既骗用户也骗作者。
- **文案只用「单数、对你一个人说」的表述**(名册 +1、你持股 1 股),读起来是用户自己的彩蛋,不是平台报表。
- **入口按钮不加红点、不加角标数字**,点亮与否即全部反馈。
- **打赏无自动到账检测**:静态个人码的到账只存在于作者微信/支付宝 App 内。**方案不设「我已支付」按钮、不伪造支付成功回调、不做轮询**——「扫码即赠,无需截图回传」是诚实边界。作者应当把**真实到账**当作唯一统计源。
- 代码内留注释 + `console.debug`(默认关):提醒作者日后别 grep 前端日志当真实活跃数。
- 若作者未来要真实数据,那是「登录 + 后端接口 + 去重计数」的另一期范围;现在埋假数会污染未来真数,故**宁缺毋假**。

### 8.2 合规与话术红线

- **对象是平台整体,不是个股**:绝不做「为这支股票点赞/打赏」,避免被读成对特定证券的推荐/收费荐股。
- **「股东/增资/表决权」是比喻**:打赏卡内必须有一行小字「本『股东/增资/表决权』均为戏称,不构成任何股权、收益分配或公司治理权利。」
- **绝不承诺收益**:文案用「加口粮/加一箱油/变更新动力」这类非回报表述;回避「更快涨」「翻倍」「有回报」;行情梗只自嘲大盘绿,不暗示打赏者收益。
- **不诱导未成年人**:见 §5.4 未成年人行。
- **用词**:用「赞赏 / 打赏 / 赠予」,**严禁「募捐 / 慈善 / 公益」**(无公募资质);作者日后自写文案也须守这条。
- **个人码风控**:金额建议主动压小额(§4),避免大额触发微信/支付宝风控或给作者带来税务/纠纷负担。

### 8.3 其他成本与风险

| 风险 | 缓解 |
|---|---|
| 换设备/清缓存丢失点赞态,用户困惑 | 确认卡小字主动声明「记在本机,属彩蛋」;彩蛋定位使其可接受 |
| 顶栏拥挤(平板 768–1023) | 点赞钮为纯图标 32px,先于主题/账号;该断点隐藏日期与状态,实测放得下 |
| 打赏对免费用户造成压力 | 两段式 + 幽灵拒绝出口 + 三重防打扰闸门(§6);白嫖体验完整是验收项 |
| 静态码到期/风控 | 码图独立成文件,作者覆盖即换;金额引导小额 |
| 可访问性 | 按钮有 aria-label;点亮用动画需配 `prefers-reduced-motion` 降级;dialog 复用 `LoginModal` 焦点管理 |

### 8.4 成本

纯前端工作量(§7.3)一次做完;零服务器/存储/支付成本;唯一长期成本是作者偶尔核对真实到账并(可选)更换码图。

## 9. 给评审的「3 个亮点 + 2 个顾虑」

### 亮点

1. **把要钱变成两段式 + 股东梗,同时用机制消灭「尴尬」**:先免费点亮给足体面出口(白嫖=完整股东体验),再以「顺带增资?」+「先不了,白嫖也是股东权益」的拒绝出口接住不花钱的人——这是所有打赏设计里对免费用户最友好的结构。
2. **防打扰是设计出来的,不是口号**:邀请只挂在「刚点赞」这一个用户主动动作后,再加终身 3 次 / 日 1 次 / 永久关闭三重闸门;入口常驻但零主动弹窗、零数字勾引,骚扰面被结构性压到最低。
3. **诚实边界写进了产品本身**:无伪造支付成功、无假统计、UI 不出现任何「N 人已赞」;用「单数、对你一个人说」的股东话术既好玩又不骗作者(真实到账才是唯一真数)。技术落点小而干净(改 1 处 2 行 + 5 个新文件,零后端零依赖)。

### 顾虑

1. **「点赞计数缺失」的双刃**:因为完全不做计数,作者端**得不到任何「多少人支持」的反馈**(连点赞量都看不到),只能看真实到账——这功能对作者的「数据回报」几乎为零,长期会不会让作者觉得「做了个寂寞」?是否应在未来期补一个登录态 + 后端的**真实**计数(而非现在造假数)?
2. **金色点亮态与自选「warning」语义靠色相拉不开**:点赞与「加入自选」都走 warning 金,用户可能混淆「这是收藏过的按钮」还是「我点过赞」。是否应换一个专属点亮色/图标形(如金色实心拇指 + 对勾角标)来区隔?这需要评审在视觉上拍板。
