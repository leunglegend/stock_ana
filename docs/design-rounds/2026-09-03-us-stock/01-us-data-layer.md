# 美股数据层 — AKShare 接口调研与数据层候选方案

- 日期：2026-09-03
- 性质：只读调研产出的设计候选（产品决策轮），不落业务代码
- 后端基线：`backend/app/services/board_data.py`（A 股板块，多源 fallback + 300s TTL 内存缓存）、`stock_data.py`（`_get_ak()` / AKShare 懒加载、`_retry` 装饰器）、`models/schemas.py` 的 `BoardInfo` / `BoardStock`
- 前端 IA 配套：见同目录 `02-us-page-ia.md`（默认后端能提供"美股指数 / 板块涨跌 / 板块成分股"三类数据）
- 本文件任务：回答"AKShare 有哪些真正可用的美股接口 / 字段口径 / 稳定性 / 非交易时段返回什么"，并给出 2 套数据层候选方案

---

## 0. 结论速览（TL;DR）

1. **指数日线：可用且已验证。** `ak.index_us_stock_sina(symbol=".INX")` 一套接口能拿到 5 个关键美股指数的日线（收盘口径）：`.INX` 标普 500、`.IXIC` 纳斯达克综合、`.DJI` 道琼斯、`.NDX` 纳斯达克 100、`.SOX` 费城半导体。返回 `date/open/high/low/close/volume/amount`，涨跌幅需用最近两根 K 收盘价自算。**新浪静态日线文件在美股盘中也不更新当日 bar**（实测 ET 午间返回仍止于上一交易日收盘），天然贴合"收盘复盘"。
2. **个股日线：可用且已验证。** `ak.stock_us_daily(symbol="AAPL")` 单请求、约 1s、~100KB，返回全历史日线 `date/open/high/low/close/volume`（无成交额、无现成涨跌幅列，需自算）。ETF（SPY）、ADR（TSM）同样可用。**不支持只取最近 N 天**，一次拉全历史。
3. **美股"行业板块→成分股"：AKShare 无现成接口（重要缺口）。** 实测源码检索确认：没有任何 GICS 行业板块接口，也没有标普 500 / 纳指 100 成分股清单接口；东财"知名美股"六分类（`stock_us_famous_spot_em`）只有 6 个粗分类且依赖东财。**结论：行业板块只能走"本地成分股清单 + 各股行业标签本地聚合"（本文件方案 B）。**
4. **东财美股系接口：当前验证环境全部不可达。** `stock_us_spot_em`、`stock_us_hist`、`index_global_spot_em`、`stock_us_famous_spot_em`、`macro_global_sox_index` 实测 HTTP 000 / Connection reset；而同环境东财 **A 股** push2his 接口 HTTP 200。疑似地域/网络对该组美股域名做限制，标注"本环境不可达，未验证是否真不可用"，**只作次选 fallback**。
5. **新浪全市场扫描接口不可作为在线数据源。** `get_us_stock_name()` / `stock_us_spot()` 源码固定 `num=20` 逐页拉全市场（数百 HTTP 请求 + 每页跑 JS 解密），实测长时间挂起，**只适合离线全量抓取**。
6. **推荐方案 B**：新浪指数日线（指数层）+ 内嵌标普 500 成分清单与 GICS 行业标签 + 新浪逐股日线（成分层，并发 + 按 ET 交易日缓存）本地聚合出 11 个 GICS 板块涨跌与领涨领跌个股；东财全市场快照作为可达时的降本加速项。

## 2. 调研到的事实

### 2.1 指数行情：`index_us_stock_sina`（实测可用，主力）

| 项 | 结论 |
|---|---|
| 函数 | `ak.index_us_stock_sina(symbol)` |
| 支持 symbol（实测） | `.INX`(标普500)、`.IXIC`(纳指综合)、`.DJI`(道指)、`.NDX`(纳指100)、`.SOX`(费城半导体) |
| 不支持（实测报错） | `.VIX`、`.RUT` |
| 返回列 | `date, open, high, low, close, volume, amount`（英文列，中文日线语义对应 日期/开盘/最高/最低/收盘/成交量/成交额） |
| 历史长度（实测） | `.INX/.IXIC/.DJI` 从 2004-01 起 ~5700 行；`.NDX` 2014-02 起；`.SOX` 2014-01 起 |
| 最近数据（实测） | 全部止于 **2026-09-02 收盘**（见下"口径"） |
| 底层 URL | `https://finance.sina.com.cn/staticdata/us/{symbol}`，返回经新浪 JS 解密后的日线 |
| 口径 | **静态日线文件，无盘后、无实时分笔**。美东 2026-09-03 12:01（盘中）请求，最新 bar 仍为 2026-09-02 全天（成交量 ~27 亿为完整日量）。→ 盘中返回"最近一个已入库交易日收盘"；当日收盘后文件应写入当日 bar（按新浪历史日线规律推断，收盘后整点未实测） |
| 涨跌幅 | **无现成涨跌幅列**，用 `close.iloc[-1]/close.iloc[-2] - 1` 自算即得收盘涨跌幅（与 A 股侧 `stock_data._stock_info_from_kline` 同法） |

单次调用示例（实测输出，2026-09-03 取数）：
```
.INX  last=2026-09-02 close=7666.60 prev=7631.47 computed_pct=+0.46
.IXIC last=2026-09-02 close=26217.83 prev=26099.77 computed_pct=+0.45
.DJI  last=2026-09-02 close=53061.95 prev=52766.88 computed_pct=+0.56
.NDX  last=2026-09-02 close=29143.33 prev=29077.22 computed_pct=+0.23
```

**非交易时段行为（本需求最关心的场景）**：新浪此静态接口给的就是"日线入库结果"，不依赖你是否在交易时段请求，天然是收盘复盘口径。东财备选 `index_global_spot_em`（实时、含涨跌幅，含道指/纳指/标普）本环境不可达，故指数层**首选新浪**。

### 2.2 个股日线：`stock_us_daily`（实测可用，主力）

| 项 | 结论 |
|---|---|
| 函数 | `ak.stock_us_daily(symbol="AAPL", adjust="")`（symbol 用纯 ticker，不带前缀） |
| 返回列 | `date, open, high, low, close, volume`（源码 `del amount`，**无成交额**；**无现成涨跌幅/涨跌额列**） |
| 历史长度 | 全历史（AAPL ~10024 行），**一次拉全量，不支持起始/结束日期参数**；实测单请求 ~1.0s、响应 ~108KB（SP500 级 ticker 同量级） |
| 兼容性（实测） | 个股 AAPL/MSFT、ETF SPY、ADR TSM 均正常；新浪备注个别复权因子错误（CIEN/AI），不复权口径不受影响 |
| 涨跌幅 | 需用最后两根 bar 收盘自算（`change_pct = close[-1]/close[-2]-1`） |
| 口径 | 同 2.1：静态日线、无盘后；盘中请求返回上一交易日收盘（实测 ET 午间 AAPL 仍止于 09-02） |

**重要代价**：该接口给的是"新浪全市场列表里的 ticker"都可拉，但**给不了中文名/英文名**（名称需另行维护，见 2.4）。

### 2.3 东财美股系接口（本环境全部不可达 — 标注未验证）

以下函数在当前网络（本机 +07，非中国大陆网络环境）实测失败，**不判死、只判"当前不可达"**，因为同一环境东财 A 股接口（`push2his.eastmoney.com`，A 股 K 线）HTTP 200 可达，说明不是东财整体被墙：

| 函数 | 作用 | 实测 |
|---|---|---|
| `stock_us_spot_em()` | 东财全市场美股快照（m:105/106/107，延迟 15 分钟），含 名称/最新价/涨跌额/涨跌幅/昨收/总市值/市盈率/换手率/振幅/成交量/成交额，代码形如 `105.AAPL` | HTTP 000（`72.push2`、`push2`、`82/92/52.push2` 均 000，curl 空响应 / 连接重置） |
| `stock_us_hist(symbol="105.MSFT")` | 东财美股日线，**直接含 `涨跌幅/涨跌额/换手率/成交额` 列**（比新浪方便），支持起止日期 | Connection reset（`63.push2his` 对美股 secid 重置；同 host 的 A 股 secid `1.600519` 却 200） |
| `stock_us_famous_spot_em(symbol="科技类")` | 东财"知名美股"六大粗分类（科技/金融/医药食品/媒体/汽车能源/制造零售）行情 | Connection reset |
| `index_global_spot_em()` | 东财全球指数实时（含道指/纳指/标普等，含涨跌幅列） | Connection reset |
| `index_global_hist_em(symbol="标普500")` | 东财全球指数日线（symbol 用中文名） | 依赖东财，未单独实测（同域失败，推断不可达） |
| `macro_global_sox_index()` | 东财宏观-费半指数历史 | 依赖东财，未实测（同域失败） |

> 判断：东财美股接口大概率"可达时可一次性给全市场含涨跌幅 + 市值/PE"的高价值数据源，但**本环境不可验证**，故设计上只作为新浪主链路的加速/补全项，绝不作为唯一依赖。若实际部署在境内网络，需在实现阶段回补一次实测。

### 2.4 名称与成分清单接口（缺口确认）

| 项 | 结论 |
|---|---|
| `get_us_stock_name()` | 新浪全美股 名称/中文名/ticker 清单。**源码结论**：`num=20` 逐页拉全市场（数百请求 + 每页 py_mini_racer 跑 JS），实测长时间挂起被中断。**不可作在线数据源**，仅离线全量抓取用 |
| `stock_us_spot()` | 同上新浪全市场实时（延迟 15 分钟），同样逐页，**不可作在线数据源** |
| `stock_individual_basic_info_us_xq`（雪球） | 公司简介（含行业信息潜在来源）——**实测 403，需 xq_a_token 登录态，不可用** |
| S&P500 / 纳指100 成分股接口 | **源码检索无**：`index_stock_cons*`（新浪/中证）只覆盖 A 股/中证指数；`index_stock_cons_csindex` 是中证；没有任何"标普500/纳指100成分股"接口。`cons.py` 里 `"标普500": {code:"SPX",market:"100"}` 仅用于东财**全球指数行情**（`index_global_hist_em`），不是成分股 |
| GICS 行业板块 / 美股"行业→成分股"接口 | **源码检索无**。全库 grep `GICS/sectorspdrs` 仅命中 A 股行业接口与行情快讯，无美股行业聚合。东财 `stock_us_famous_spot_em` 是唯一"美股分类"，但只有 6 个粗分类且非 GICS、且本环境不可达 |
| 个股行业标签来源 | akshare 内无稳定可用来源（雪球 403；东财 F10 `stock_financial_us_report_em` 只有报表无行业；`stock_us_valuation_baidu` 只有估值）。→ **行业标签只能外部静态快照内嵌**（如标普官网/公开数据集/Wikipedia 的 ticker→GICS 表，季频维护） |

### 2.5 关键源码事实速记

- `stock_us_sina.py`：`get_us_stock_name`/`stock_us_spot` 均 `for page in range(1, page_count+1)` + `num=20`；`stock_us_daily` 单 URL 拉全历史。
- `index_stock_us_sina.py`：`index_us_stock_sina` 请求 `finance.sina.com.cn/staticdata/us/{symbol}`，JS 解密后建 DataFrame，纯历史日线。
- `stock_hist_em.py`：`stock_us_spot_em` 打 `72.push2.eastmoney.com/api/qt/clist/get`、`fs=m:105,m:106,m:107`，映射列含 `代码=编码.简称`（`105.AAPL`）；`stock_us_hist` 打 `63.push2his.eastmoney.com`、klt 101/102/103，列含 `涨跌幅/涨跌额/换手率`。
- `index_global_sina.py`：`index_global_name_table` 20 个**非美**全球市场（UKX/DAX/…），**不含**美股指；美指不要走这条路。

## 3. 字段口径、稳定性与限流总结

### 3.1 涨跌幅口径（收盘 vs 盘中、是否含盘后）

| 源 | 涨跌幅口径 | 盘后 | 备注 |
|---|---|---|---|
| `index_us_stock_sina` / `stock_us_daily`（新浪静态日线） | **上一交易日收盘价口径自算**（无现成涨跌幅列）；实测美股盘中（ET 12:01）最新 bar 仍是上一交易日完整日量 → 盘中查询=最近收盘，**不含当日盘中与盘后** | 无 | 最适合"收盘复盘"；当日收盘入库时机按新浪惯例推断为收盘后，未在收盘后实测 |
| `stock_us_spot_em`（东财，本环境不可达） | 现成 `涨跌幅` 列，官方注明**延迟 15 分钟**；收盘后延迟无影响 | 无独立盘后数据 | 若可达，是"全市场含涨跌幅"的最省事来源 |
| `stock_us_hist`（东财日线，本环境不可达） | 现成 `涨跌幅/涨跌额` 列，按自然日收盘算 | 无 | 字段最贴合 `BoardStock` |

### 3.2 非交易时段 / 节假日 / 休市返回什么

- 新浪静态日线：只含**已入库的交易日**，周末/节假日无当日行，取 `iloc[-1]` 即最近收盘交易日；美股盘中也不出现当日行（见 2.1 实测）。→ 全年任意时刻请求都能拿到"最近一个完整交易日收盘"，对复盘是无脑安全的。
- 东财（不可达，推断）：`spot_em` 非交易时段返回上一交易日收盘的静态快照（延迟口径），`hist` 按自然日返回。

### 3.3 稳定性与限流风险

| 源 | 稳定性评估 |
|---|---|
| 新浪 `staticdata/us/{symbol}` 单 symbol 日线 | 实测 ~1s/请求、稳定 200；**限流风险：逐股高频拉会被断**（本项目仓库 A 股侧新浪日线同样被作主源，配合 `_retry`）。单次全量刷新 500 只 ≈ 500 请求，需**并发 + 按 ET 交易日缓存**压到每日一次 |
| 新浪全市场分页（`stock_us_spot`/`get_us_stock_name`） | 数百请求 + 每页 JS 解密，**实际不可作在线源**（实测挂起数分钟无结果） |
| 东财美股（clist/kline/spot/global） | 本环境全 000/重置 → **不可达**；境内部署可能可达，标注待回测 |
| 雪球 | 403，无 token 不可用 |

## 4. 两套候选数据方案

统一产品目标（对齐 `02-us-page-ia.md`）：收盘后复盘 —— 指数涨跌 → 行业板块涨跌榜 → 板块内领涨领跌个股。两方案都建立在"新浪静态日线已验证可用"这一事实上，区别在**行业板块怎么来**。

### 方案 A：纯 AKShare 现成接口聚合（不强依赖本地行业表）

- **指数层**：`index_us_stock_sina` 5 指数（已验证）→ 收盘涨跌幅自算。
- **板块层**：AKShare **没有**美股 GICS/行业板块接口。唯一沾边的是东财 `stock_us_famous_spot_em` 六分类（科技/金融/医药食品/媒体/汽车能源/制造零售）——非 GICS、覆盖仅"知名美股"子集、且本环境不可达。
- **成分股/领涨领跌**：
  - 若东财 `stock_us_spot_em` 可达：一次全市场快照，按"是否属于某分类"粗筛（分类只能靠名称/代码前缀猜，无归属标签）→ 质量差。
  - 否则退回新浪全市场 `stock_us_spot`（逐页数百请求，不可在线用）。
- **数据来源清单**：新浪指数日线 + （东财知名美股分类 / 东财全市场快照，均本环境不可达）。
- **覆盖范围**：指数完整；板块仅 6 个粗分类或缺失；成分领涨领跌不可靠。
- **成本/风险**：无本地清单维护成本；**风险高**——板块需求基本落空，东财不可达时无可用板块数据。
- **对"收盘复盘"适配度**：低。只能满足"指数涨跌"，**满足不了"行业板块涨跌 → 领涨领跌个股"主路径**。

### 方案 B：本地成分清单 + 行业标签，本地聚合（推荐）

- **指数层**：`index_us_stock_sina` 5 指数（已验证）→ 收盘涨跌幅自算。
- **成分清单与行业标签**：内嵌一张**静态快照表**：`ticker → (名称EN/CN, GICS 一级行业)`，范围取 **标普 500（约 503 只）** 或可选 **纳指 100**。GICS 11 个一级行业即"板块"。清单为季频维护的静态数据文件（不写成业务代码，作为数据资产 + 刷新脚本留二期）。→ 弥补 2.4 的缺口。
- **成分股行情（领涨领跌）**：
  1. 首选加速：东财 `stock_us_spot_em` 全市场快照（可达时），一次请求拿到全部 ticker 的 `涨跌幅/最新价/市值/PE`，按清单归属聚合成板块 + 板块内排序 —— 500 只全覆盖、1 个请求。
  2. 兜底主链路：新浪 `stock_us_daily(ticker)` **并发**（如 8–16 线程）逐成分拉取，末两根 bar 自算 `收盘/涨跌幅`；500 只 × ~1s / 并发 16 ≈ 40–60s 一次，配合按 ET 交易日缓存做到**每日仅刷新一次**。
- **板块聚合口径**：板块 `change_pct` = 成分股等权平均当日涨跌幅（可另给市值加权口径）；`rise_count/fall_count/stock_count` 实算；`leading_stock/leading_change` = 板块内当日涨幅最大者；`total_turnover/turnover_rate` 新浪路径无成交额 → 置 0/空（东财可达时补全）。
- **数据来源清单**：新浪指数日线（主力，已验证）+ 新浪逐股日线（主力，已验证）+ 内嵌标普500/GICS 静态表（数据资产）+ 东财全市场快照（加速可选，未验证可达）。
- **覆盖范围**：指数 5 个；板块 11 个 GICS 一级行业；成分约 503 只（覆盖美股总市值 ~80%），每板块成员 20–80 只，领涨领跌有意义。
- **成本/风险**：需维护 1 张季频静态成分表（数据获取脚本 + 校验）；每日全量刷新 500 次逐股请求有被新浪限流风险（用并发 + 单日一次缓存 + `_retry` 缓解）；聚合口径为"等权"，与东财/A股板块口径不完全一致（页面需注明）。
- **对"收盘复盘"适配度**：**高**。完整覆盖 指数→板块→成分领涨领跌 主路径，且数据全为收盘口径。

## 5. 落到平台现有代码模式的映射设计（推荐方案 B 展开）

### 5.1 服务层骨架（新增 `backend/app/services/us_data.py`，参照 `board_data.py`）

```
get_us_index_recap()          # 5 指数：index_us_stock_sina → 自算涨跌幅 → List[IndexQuote]
get_us_industry_boards()      # 标普500成分按 GICS 聚合 → List[BoardInfo]（按涨跌幅排序）
get_us_board_stocks(sector)   # 某 GICS 板块成分 → List[BoardStock]（按涨跌幅排序）
```

- 复用 `stock_data._get_ak()` 懒加载、`stock_data._retry`。
- `_get_ak()` 已存在，美股服务同样延迟导入 AKShare。

### 5.2 缓存策略（关键：不能照抄 300s TTL 的"高并发短 TTL"）

`board_data.py` 的 `_CACHE_TTL=300` 适合 A 股"盘中多次刷新"；美股的成分行情是**逐股 500 次请求换来的**，若 300s 就重刷会变成 500 req/5min ≈ 高频打新浪，必被限流。建议：

- **主缓存键 = 美东交易日（ET date）**：取数后记录 `as_of_date`（最近一根 bar 的日期）。同一 ET 交易日内任何请求直接命中缓存，**不重复拉 500 只**。
- **短 TTL 覆盖盘中过渡**：缓存命中后再叠加一个 60s 的"软 TTL"用于页面兜底，但**真正的全量重拉只在 ET 日期变化时发生**（每日 1 次）。
- 指数层 5 个请求很轻，可放宽到 `_CACHE_TTL=300` 甚至实时自算，不影响。
- 首次请求同步加载（沿用现有模式），失败返回过期缓存 + 打印告警。

### 5.3 字段映射到现有 schema

| 平台字段 | 美股来源 | 说明 |
|---|---|---|
| `BoardInfo.name` | GICS 一级行业中/英名（如 `信息技术 Information Technology`） | 与 A 股板块同名空间冲突 → 接口加 `market` 参数/前缀 |

| `BoardInfo.change_amount` / `total_turnover` / `turnover_rate` | 新浪路径无成交额/换手 → **0 或留空**；东财可达时补 | 诚实留空，避免假数据 |

## 6. 推荐方案与理由

**推荐方案 B（本地标普 500 成分清单 + GICS 行业标签本地聚合，新浪静态日线为主链路，东财为加速/补全项）。**

理由：

1. **A 方案在产品主路径上不成立**：AKShare 没有美股行业板块接口，板块需求只能靠本地聚合实现；"纯现成接口"在板块层没有可用数据，适配度低。
2. **主数据源已实测可靠**：新浪指数/个股静态日线在"本环境 + 美股盘中"都能稳定返回最近收盘，天然匹配"收盘复盘"；不依赖当前不可达的东财。
3. **成本可控**：标普 500 + GICS 是公开、季频变化小的静态数据；成分行情按 ET 交易日缓存后每日仅全量刷新一次（并发 ~1 分钟），不会打爆新浪。
4. **schema 兼容**：现有 `BoardInfo`/`BoardStock` 几乎字段级复用，前端 IA（02 文档）的组件范式直接可用，仅需对美股 ticker 与缺失字段做说明。
5. **A 股联动二期留口自然**：`market="us"` + ticker 隔离，后续加映射表不动数据层骨架。

**主要取舍要承认**：新浪路径拿不到"成交额/换手率/市值/PE"，复盘表格这些列在美股页要么隐藏要么显示"—"；板块涨跌幅是等权自算口径而非交易所官方口径。东财若在境内网络可达，可在二期把 5.4 的顺序反过来并补全字段——但当期实现不能赌东财。

## 8. 二期与未决问题

1. **东财可达性回测**：若部署在境内网络，需实现前实测 `stock_us_spot_em`/`stock_us_hist`；可达则全市场快照单请求替代 500 次逐股拉取，并补全成交额/PE/市值字段。
2. **成分清单获取与校验**：标普 500 成分 + GICS 标签建议做成独立数据脚本/资产（来源：标普官网季度调整公告、公开 GICS 映射数据集），入库前按数量（≈503）、行业分布、ticker 格式做校验；季频更新。
3. **聚合口径**：板块涨跌用等权 or 市值加权需产品确认；若与 A 股板块榜并列展示，需在 UI 标注"美股板块为标普500成分等权聚合，非官方板块指数"。
4. **盘中 vs 收盘**：页面若在美股盘中打开，数据仍是上一交易日收盘（新浪静态文件特性）。需与 IA 对齐：美股页定位"收盘复盘"，盘中打开时显示 `as_of` 并提示"美股盘中，显示上一交易日收盘"。
5. **是否引入官方板块 ETF 作为对照**：如 XLB/XLC/XLY 等 11 个 GICS 板块 ETF 可用 `stock_us_daily("XLK")` 单请求拿到板块自身涨跌幅（已验证 ETF 可拉），可作为本地聚合结果的**交叉校验**（不替代领涨领跌需求）。
